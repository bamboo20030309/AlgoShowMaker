# AlgoShowMaker 教材製作

目標是讓觀眾看懂「程式為何這樣執行」，並讓作者能修改教材。使用者的題目、程式、指定格式及教學目標優先。

## 選擇任務與讀取資料

- 寫繪圖註解：讀 [繪圖語法](references/directives.md) 及 [幀與事件](references/frames-events.md)。
- 選擇資料結構或範例：讀 [結構與範例](references/structures-examples.md)。
- 製作投影片：讀 [原生投影片](references/slides.md)；含動畫時也讀前三項。
- 只接受單檔提示的 AI：使用 [精簡版](QUICKSTART.md)，適用於核心語法與教材草稿。

本包核心語法依 2026-10-07 的專案 commit `cda1219eb407845e8ebbae22d7a30580b0ec7f1f` 整理。進階選項或遇到版本差異，查專案根目錄 `ALGORITHM_VISUALIZATION_DIRECTIVE_MANUAL.md` 與實際 parser。無 repo 存取權時，可查 [對應版本手冊](https://github.com/bamboo20030309/AlgoShowMaker/blob/cda1219eb407845e8ebbae22d7a30580b0ec7f1f/ALGORITHM_VISUALIZATION_DIRECTIVE_MANUAL.md)。本包可獨立使用核心語法；未提供的進階語法應先查證。

## 製作流程

1. 確認輸入、輸出、索引起點、變數意義及使用者要交付的內容。已有程式時先閱讀實作，整理不變量、更新與分支；缺少必要資料才詢問。
2. 選小輸入，列出預期中間狀態與答案。包含正常路徑和關鍵分支，例如 KMP 失配回退；避免只展示最順利的輸入。
3. 先寫教學分鏡：每個階段的問題、畫面、對應程式位置、說明與預期結果。指出當前狀態和下一步的原因。
4. 以現代 `// @...` 註解建立最小動畫，再加入樣式、文字、排版及必要事件。保持原程式的演算法、型別、邊界與標準輸出；若須修改邏輯，明確列出原因和差異。
5. 投影片依「問題 → 狀態表示 → 規則／不變量 → 程式 → 動畫 → 練習 → 檢核」安排。文字、程式、公式及結構使用各自可編輯元件。
6. 有執行環境時檢查編譯、答案、trace、關鍵畫面與投影片匯入。依實際修改範圍使用 repo 的驗證規範，不因教材註解就執行全部 regression。
7. 交付程式／投影片、輸入與預期答案、關鍵幀對照、驗證結果及限制。沒有執行能力時明示「尚未實際編譯／播放／匯入」，附人工檢核步驟。

## 指標與樣式偏好

- 有陣列遍歷需求時，優先使用指標呈現目前索引、移動方向及多個遍歷位置；例如用 `@frame arr[i,j]` 顯示指標。指標的呈現效果優於只用 style 塗色，不以逐格改色取代遍歷指標。
- 使用 `background`、`point`、`mark`、`focus` 這四種 style 時，省略顏色參數，直接沿用各自的預設塗色，例如 `@style arr[i] focus`；不要額外指定色碼或顏色別名。這項偏好只約束教材製作，不修改引擎預設色或覆蓋既有物件的自訂顏色。

## 預設設定與畫面連續性

- 專案已有許多預設設定；先確認省略後的行為符合需求，能省略就省略。只明寫偏離預設或教學必要的設定，避免重複指定顏色、標籤、排版或事件開關；必要的關閉設定與自訂值仍須保留。
- 後續仍需呈現的物件，盡量在相關連續幀中維持顯示，沿用相同物件身分、相對位置與指標關係，避免因分鏡漏列而反覆退場、重新入場或跳位。檢查相鄰幀的觀看連續性；確實結束生命週期或需要切換教學階段時才安排退場，不以過期快照冒充目前狀態。

## 繪圖邏輯與對應關係

- 繪圖專用的條件、暫時計算與批次操作，優先使用指令的 `when`、`@let` 與 `@for ... @endfor`，盡量不新增原生 C++ 的 `if`、變數或迴圈來控制繪圖。`@let` 是幀內唯讀運算別名，不是可修改的 C++ 變數；依手冊確認各指令支援的條件與批次範圍。
- 確實需要 C++ 輔助繪圖時，用 `// @code hide` 與 `// @endcode` 包住必要的輔助程式區段，避免干擾教學程式與事件。只隱藏繪圖輔助邏輯，不因此隱藏解法本身的重要步驟。
- 某些資料來源、目的或依賴關係難以用事件動畫清楚呈現時，可使用 `@arrow` 強調對應關係，搭配必要說明。箭頭端點須對應實際可見物件；能正常呈現的事件仍保留，不以箭頭掩蓋解析或目標綁定錯誤。

## 指令選用與版本核對

製作教材時，先使用以下既有能力減少重複指令及 C++ 繪圖輔助邏輯。依教學需要選用，不要求每個範例全部使用；完整語法與限制以專案手冊及當前 parser 為準。`char(s)`、矩陣獨立列／欄指標與 pointer color 已在 intergration 的 `cde8028` 實作；若使用較舊部署，先核對版本。

## 共用預設設定：`@defaults`

- 多個連續幀共用鏡頭、物件呈現或樣式時，將共同設定放進 `@defaults`，並以 `@enddefaults` 結束。各幀只寫當下要顯示的物件與例外設定，避免複製整段配置後漏改其中一幀。
- 例如插入排序每幀都聚焦 `arr`，可在預設區塊設定 `@camera focus arr offset(0,20) zoom(2.0)`，不必在每個 `@frame` 後重複寫鏡頭。
- 預設區塊不是一般程式流程，不用來建立新幀或執行 keep／exit。只有真正共用的設定才放入；單一階段的特殊效果放在該幀，避免影響後續畫面。支援項目與局部覆寫行為依手冊確認。

## 可重用場景與組合：`@preset`

- 將反覆使用的物件、相對位置、樣式、文字或箭頭包成 `@preset 名稱 ... @endpreset`。以 `@frame use 名稱` 使用，適合河內塔場景、八皇后棋盤與 LCS 表格等固定配置。
- 依責任拆成可組合的小區塊，例如基本表格、答案陣列與游標各一個 preset，再用 `@frame use lcs_view, lcs_answers, lcs_dfs_cursor` 組合。讓不同教學階段只替換必要部分，維持物件身分與畫面連續性。
- 不假設 preset 具有尚未實作的參數傳入能力。也不假設局部 `@object` 只改一個欄位：重新宣告同一物件可能取代整份物件配置，應核對標籤、range、display 等設定是否保留；新增游標優先使用獨立 `@pointer`。

## 繪圖計算與唯讀別名：`@let`

- 只為文字、範圍或樣式需要的暫時計算，優先使用 `@let 名稱 = 運算式`，不在 C++ 新增與解法無關的變數。例如 BIT 的 `@let lb = i & -i`，或八皇后的 `@let bit = 1 << (N - 1 - column)`。
- `@let` 是幀內唯讀運算別名，不是 C++ 的可變狀態，不用它累加計數、模擬賦值事件或保存跨幀歷史。別名可供支援的文字插值、條件與繪圖運算使用；引用格子座標時，依對應功能的逐格求值規則計算。
- 保留演算法真正使用的 C++ 變數及更新。別名避免與既有變數或保留名稱衝突；需要跨階段狀態時，先確認能否從原始資料推得，不為了方便繪圖偷偷改變解法。

## 繪圖指令的條件顯示：`when`

- 某個畫面、說明或效果只在特定條件成立時呈現，將條件寫在支援的指令後，例如 `@text "到達最左邊" at arr.bottom when j < 0`。避免為了決定是否畫圖，在 C++ 多包一層 `if`。
- 樣式條件可依格子資料逐一判斷，例如 `@style arr[0:i] background when value > key`；它描述哪些格子套用效果，不改變陣列內容，也不代替真正的比較或賦值。
- 區分「條件不成立而不畫」與「演算法沒有執行」。不要用 when 隱藏錯誤事件或錯誤結果；也不要假設所有指令都支援相同條件語法，依手冊確認求值時機與作用範圍。

## 依格子內容與座標求值：`value/index/row/column`

- 在支援逐格求值的樣式及 display 中，直接使用 `value`、`index` 或二維的 `row`、`column`，避免逐格建立 C++ 顯示資料。例如插入排序依 value 與 key 比較上色，八皇后依 row／column 判斷攻擊範圍。
- 這些名稱代表正在處理的格子，不是新的 C++ 變數。相同條件套用到一段範圍時，會依各格的內容與座標判斷；涉及另一個陣列或目前游標時，明確引用原始變數。
- 不把一維 index 與矩陣列欄座標混用，也不假設純量指令具有格子上下文。先確認物件型態、索引起點與實際可見範圍，避免樣式看似正確卻對應到錯格。

## 批次繪圖與箭頭生成：`@for`

- 多個格子要建立同型箭頭或效果時，用 `@for ... @endfor` 批次描述。例如 LCS 可用兩層繪圖迴圈走過列與欄，建立各格的轉移箭頭，不需手寫大量指令。
- 明確指定批次範圍與必要步長，例如 `@for rr in [1:rows]`；內部再用條件決定哪些箭頭或效果需要呈現。將重複的繪圖規則留在指令層，避免插入 C++ 迴圈干擾事件。
- 繪圖迴圈不執行演算法更新，也不應取代真正計算 DP 或排序的迴圈。檢查批次端點均為可見物件，避免產生越界、重複或沒有教學意義的箭頭；具體展開語法依手冊使用。

## 取得迴圈實際首末值：`iteration.first/last`

- 需要說明某輪實際處理的區間時，使用 `iteration.first(i)`、`iteration.last(i)`，避免另外建立只為繪圖記錄首末值的 C++ 變數。適合 BIT 跳躍索引與線篩內層迴圈等非固定步進情況。
- 區分「程式寫出的理論界線」與「實際執行到的值」。例如線篩以 `prime[0:iteration.last(j)]` 說明已使用的質數範圍，應對照該輪執行記錄，不能自行推成整個 prime 陣列。
- 首末值依迴圈執行上下文解析，不把其他呼叫或另一輪的結果當成目前資料。零次迭代、提早退出等情況先核對可取得的值與畫面，不自行填入看似合理的索引。

## 取得前一動畫幀的值：`prev(...)`

- 變數已更新，但文字需要交代上一幀的狀態時，用 `prev(運算式)`。例如選擇排序更新 min_idx 後，用 `${prev(min_idx)}` 說明原先最小值的位置，不另加 old_min_idx 等顯示變數。
- `prev(...)` 對照前一動畫幀，不等同目前幀內某次賦值前的瞬間。若要解釋單一事件的前後值，應核對事件資料，或查證 `before(...)` 的適用規則，而不是混用兩種時間語意。
- 前一幀沒有該變數、變數生命週期已切換或處於首幀時，先確認解析結果。文字應符合真實執行歷史，不以固定值補出不存在的前態。

## 原始資料的位元顯示：`bits(...)`

- 教學重點是遮罩、位移或狀態壓縮時，用 `bits(物件, 寬度)` 將整數或整數陣列呈現成位元格子。八皇后可直接顯示 board、L、M、R，不另建只為畫圖的 0／1 陣列。
- 按教學問題明確選擇位元寬度與顯示方式，例如 `bits(board, N)`；需要棋盤符號時再搭配 display，保留底層值與原始演算法的讀寫關係。
- bits 是顯示轉換，不把原整數改造成另一份可更新資料。位元方向、索引對應及邊界須對照實際畫面；不要因為換了呈現方式，就假設所有事件都能自動找到可見目標。

## 原字串的逐字顯示：`char(s)`

- 字串比對需要逐字格子及索引游標時，直接用 `@frame char(s)[i,j]`，讓原字串 s 以字元陣列呈現。避免為 KMP 等演算法另建 vector<string> pat，造成比較事件操作 s、畫面卻只顯示 pat。
- char(s) 保留來源物件名稱與身分；後續樣式與指標仍以 s 為目標，例如 `@style s[i] highlight` 或 `@pointer i at s`。演算法本身仍使用 string 與原本的 s[i] 讀寫。
- 這是 string 的顯示轉換，不接受任意非字串型態。非 ASCII 文字須核對 C++ 字串位元組索引與字形顯示的對應，不假設 std::string 的索引就是 Unicode 字元序號。

## 格子文字與符號的自訂呈現：`display(...)`

- 格子要顯示教學符號或運算說明時，以 `display("...")` 改變呈現文字。例如八皇后使用 `display("${value ? '♕' : '　'}")`，費式遞迴使用 F(n) 說明呼叫狀態。
- 直接從原始 value、變數或繪圖別名產生顯示內容，不另建顯示字串陣列。相同的底層狀態可以有不同教學外觀，但比較、賦值與標準輸出仍依原始資料。
- display 不改變格子的資料型態或數值，也不會把事件來源轉成顯示字串。符號與說明避免遮蔽關鍵值；需要觀眾核對計算時，保留足夠的原始數值或對照說明。

## 矩陣列／欄標籤與字串對照

- DP 表格對應兩個字串或序列時，優先使用 `row-labels`、`column-labels` 建立軸標籤。LCS 可用 `row-labels("",S), column-labels("",T)`，把字元與表格位置直接對照，不另建文字物件逐個排版。
- 標籤數量與位置應符合矩陣定義。LCS 的零列／零欄表示空字串，因此前面的空白標籤有實際意義；不能為了美觀刪除後，讓字元與 DP 索引錯一格。
- 軸標籤、格子內容及指標各負責不同資訊。新增游標時保留已有標籤設定，不重新宣告一份精簡矩陣導致原標籤消失；自訂標籤也不改變底層索引起點。

## 節點資料合併、隱藏與格式：`fields/hide/format`

- 同一個節點由多份資料共同描述時，用 fields 合併呈現。例如線段樹把 tree、sets、lazy 顯示在同一節點，避免在 C++ 組字串或建立另一個展示結構。
- 使用 hide 隱藏不需要顯示的哨兵值，再以 format 區分賦值與增量。例如 `fields(tree,sets,lazy), hide(sets=LM,lazy=0), format(sets=assign,lazy=signed)`，讓觀眾看懂目前節點與待處理操作。
- 合併欄位須對應同一節點的索引，主要欄位與順序按 renderer 規則設定。hide 只影響外觀，不刪除資料或跳過 lazy propagation；事件能否對應到欄位仍須實際驗證。

## 直接隨物件宣告索引指標

- 顯示陣列與遍歷位置時，可在物件寫法直接帶索引，例如 `@frame arr[i,min_idx,j]`；二維物件可使用 `LCS[i][j]`。不需額外建立數字框或箭頭物件來模擬游標。
- 一維多指標依作者寫出的序列安排。相鄰幀盡量維持同一順序；教學確實需要交換角色排列時才調整，避免只是重寫 frame 就造成指標跳位。
- 這些指標應引用演算法真正更新的變數，讓移動事件能對應到畫面。索引越界或變數退場時，依既有規則處理，不把指標強留在不存在的格子；只需新增游標時可改用獨立 @pointer。

## 不重新宣告物件的獨立指標：`@pointer`

- 已有物件的標籤、格式與範圍都設定好，只需要增加游標時，用獨立 `@pointer`，避免重新寫 @object 後覆蓋原有呈現。一般陣列可寫 `@pointer i at arr`，省略索引時直接使用 i 的值。
- 需要指向 layout 中已保存的節點時，使用實際支援的 selector。Merge Sort 可寫 `@pointer i at merge_tree.children[0]`、`@pointer j at merge_tree.children[1]`，讓左右游標指向各自子樹。
- 區分原始索引、局部副本索引與保留節點的範圍。只有對應關係確實需要時才寫偏移運算式，不能因左右子樹長得相似就把指標綁到另一個節點；越界時應隱藏。

## 矩陣獨立列／欄指標：`.row/.column`

- 矩陣需要分開顯示目前列與欄時，使用 `@pointer i at dp.row`、`@pointer j at dp.column`。省略 [i]／[j] 即使用指標變數值；列指標在左側，欄指標在上方。
- 獨立指標不改變 dp 的標籤、範圍、display 或其他 renderer 配置。軸標籤隱藏時仍有定位點，不必為了顯示游標把原本不需要的標籤打開。
- 明寫 .row／.column 即指定外側軸位置。marker-layout(inner) 的自動格子定位不改變此明確目標；marker-layout(none) 關閉自動指標，但明寫的 @pointer 仍呈現。越界索引隱藏，不是將游標固定到最近的邊界。

## 指標角色的顏色設定：`color`

- 多個游標需要區分角色時，可在任一 @pointer 後加 color，例如 `@pointer i at dp.row color AV_blue` 或 `@pointer j at arr color #e65100`。陣列、矩陣軸與支援的 layout 指標使用同一寫法。
- 指定顏色套用到標籤底色、外框與箭頭線，文字保留原有深色；支援 AV 別名與 CSS 顏色寫法。不需要特別區分時省略 color，沿用原本預設外觀，舊 Trace 缺少此欄位也維持預設。
- 顏色用來表達角色，相關幀盡量保持一致，避免每幀換色。pointer 的可選顏色不改變 background／point／mark／focus 應使用預設色的教材偏好；不要把兩套設定混為一談。

## 遞迴樹與線性序列的自動排版：`@layout`

- 遞迴呼叫或多輪結果需要規律排列時，使用 recursion／linear layout，不手算每個節點的絕對座標。費式與河內塔可沿呼叫關係排成樹；Merge Sort 每輪結果可沿 top-down 線性排版。
- 以方向、間距、對齊與必要的預覽設定控制整體布局，物件用 in 指定所屬 layout。先確定要表達的是呼叫關係、處理順序還是歷史結果，再選排版，避免只為塞進畫面改變關係。
- layout 只管理呈現，不建立演算法狀態。需要保存節點時配合 keep，額外操作節點使用已支援的 branch；不假設所有 renderer 或 anchor 都具有同一套 layout selector。

## 歷史畫面與物件快照：`@keep`

- 需要比較目前狀態與先前結果時，使用 keep 保存既有畫面或物件，不在 C++ 建立歷史資料副本。例如排序完成一輪後 `@keep last`，或八皇后保存棋盤到遞迴 layout。
- 明確區分保存整個前幀與保存指定物件。只需要陣列值時指定該物件；確實需要完整前幀配置才用 keep last，並核對保存的樣式、指標、文字與位置是否符合教學目的。
- keep 是凍結的歷史快照，不是目前變數的另一個即時視圖。保存節點要安排在合適的 layout 或位置，避免後續新畫面與快照重疊；不要把過期快照冒充正在更新的資料。

## 物件間的相對定位與錨點：`@place`

- 兩個物件的關係比絕對位置重要時，用 `@place ... at ... offset(...)`。例如 `@place temp.top-left at num.bottom-left offset(0,72)`，讓 temp 跟著 num 排在下面，不依賴硬編的畫布座標。
- 錨點按對齊需求選擇，例如共同左邊界、上下間距或中心對齊。河內塔、前綴和與雙陣列畫面先建立相對關係，再調必要的 offset，減少物件尺寸改變後的排版修正。
- 被參照物件須在該幀可見，避免循環定位或引用已退場目標。歷史快照與目前物件可能外觀相同，仍須核對實際端點；相對定位也不能代替指向指定格子的索引綁定。

## 共用效果的多目標、多樣式與預設色

- 多個目標確實要套用相同效果時，合併成同一條指令，例如 `@style L, M, R background when value == 1`。同一格需要多個支援樣式時，可組合寫法，避免複製內容後出現設定不一致。
- background／point／mark／focus 優先省略顏色，使用各自預設效果；不同 style 的預設不能假設相同。只有教學確有必要且符合使用者指定時，才另作偏離預設的安排。
- 合併的是相同規則，不是不同意義的格子角色。目標型態、條件求值與範圍都要有效；若不同物件需要不同條件或文字說明，就保持分開，不為縮短程式犧牲可讀性。

## 事件動畫控制與輔助程式隱藏：`@code hide`

- 重複且沒有額外教學意義的事件，可依支援設定選擇性停用動畫，例如 `@events animate off`，把觀看重點留給重要比較、賦值與索引移動。先判斷教學目的，不機械式把所有事件關掉。
- 確實需要 C++ 輔助繪圖時，用 `// @code hide` 與 `// @endcode` 包住必要的輔助區段，避免它占用教學程式與事件畫面。能用 when／let／for 完成的顯示邏輯仍優先放在指令層。
- 隱藏或停用呈現不代表演算法沒有執行，也不能用來掩飾 trace 解析錯誤。保留解法的重要更新與分支；資料來源或目的難以用事件清楚表達時，可補 arrow 說明，仍核對原事件與答案。


## 原始變數與事件呈現

- 儘量直接顯示演算法實際讀寫的變數，不為展示另建與解法無關的變數或複製資料。相同內容的展示副本不是原變數的事件目標，可能使已解析的事件找不到可見目標而無法播放。
- 字串可按字元陣列解析與呈現；優先顯示原字串及其索引指標，不為逐字展示另外建立 `vector<string>` 或其他副本。保留原演算法的資料型別與讀寫邏輯。
- 以大部分與解法有關的比較、賦值、交換及指標移動都能解析並播放為目標。確認事件來源、目的與運算元能對應到可見物件；驗證實際動畫，不只核對最終畫面或幀數，也不以 style 取代事件。
- 只有確認既有呈現能力不足時才增加必要的展示資料，並說明理由及無法呈現的事件。展示副本須同步且不影響結果，不假設原變數事件會自動轉移到副本。

## 必須避免的錯誤

- 不發明指令、renderer、事件名稱或投影片欄位。
- 不把現代註解式繪圖與舊 `AV.hpp` 的 `av.draw`／`av.start_draw()` 混用。
- 不把 `@frame` 視為自動說明工具：原因要用文字與程式對照寫出來。
- 不把幀的最終狀態當成每個事件發生時的狀態；不以關閉事件動畫掩飾錯誤結果。
- 不把故事板或 JSON 改副檔名成 `.asmdeck` 後宣稱可匯入。
- 不宣稱保留 AC 身分或改善學習成效，除非有對應驗證。註解版應檢查 stdout 與原程式一致。
