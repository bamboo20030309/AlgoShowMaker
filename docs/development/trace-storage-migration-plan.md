# 公開 Trace 全部移出 Git 的評估

狀態：2026-11-09，使用者要求評估；尚未授權移動、刪除、上傳外部儲存或改寫 Git 歷史。

## 範圍與建議

建議將公開範例的完整 Trace JSON 改放獨立持久化目錄，部署時掛給 backend 與 Nginx 唯讀提供。Git 保留小型索引、校驗清單、教材原始碼與只含 Trace ID 的投影片。先維持原有網址，再視需求將同一目錄換成物件儲存；不必為此立即增加新的服務。

目前 280 筆內容 ID 合計約 837 MiB，其中現行 36 筆約 114 MiB，其餘歷史 244 筆約 723 MiB。建議第一階段完整搬存全部 280 筆，避免尚未盤點的舊投影片失效。雲端使用者產生的 Trace／分塊仍沿用既有資料庫與權限流程，不包含在本次公開資產搬移中。

## 儲存方式比較

| 方式 | 適合目前環境的理由 | 必要成本或限制 |
|---|---|---|
| 專用持久化目錄＋校驗資產包 | 可沿用現在 Docker／Nginx，同一主機不額外依賴網路儲存 | 新主機部署須先還原資產包；主機外仍需備份 |
| 物件儲存＋同網域代理 | 程式部署與大型資料分離，方便多台伺服器共用 | 要設定儲存位置、權限、網路錯誤與快取；需選定實際服務後估費用 |
| Git LFS | 保留類似 Git 的操作 | 仍有下載、儲存與部署憑證需求；不會自動移除既有 Git 歷史，未解決全部需求 |
| 只保留程式碼、部署時全部重跑 | 現行結果可以重建 | 歷史 Trace 未必能重現同一內容 ID，舊分享可能失效；不建議作為唯一保存方式 |

## 應維持的契約

- 投影片內的 Trace ID 不變，既有 index 的 ID→檔名映射與 legacy 檔名不變。
- `/deck-traces/<命名檔>.json`、`/deck-traces/<ID>.json` 都保留；後者繼續經 Express 解析索引。
- 公開清單與索引仍可更新；不可變 JSON 可以長期快取，索引更新時重新驗證。
- 首幀預覽與 default-animation 的既有網址不因這次移動而改變。
- Trace 缺失要明確顯示並走既有重建流程，不能默默使用不同 ID 的結果。

## 實作與部署步驟（待批准）

1. 唯讀建立完整資產清單：ID、相對檔名、位元組數與 SHA-256。核對全部 ID 可讀、內容符合 ID，列出仍需保留的舊網址。引用盤點包括公開教材／預設動畫、可取得的本機草稿與匯出檔、目前 Mongo 投影片；不輸出帳號資料。離線電腦與其他部署的未知引用不能宣稱已掃完。
2. 將所有公開 Trace 和必要索引複製到 repo 外資產目錄，保留原件；製作可還原資產包，另放主機外備份。重新解包並逐檔校驗，不以「打包成功」代替可還原驗證。
3. 後端加入可設定的公開 Trace 根目錄，預設相容目前 public 路徑。Nginx 將同一目錄掛至原 `/deck-traces/` 網址。兩者必須使用同一版索引；不能只換 Nginx，讓 Express 舊 ID 查詢仍讀舊目錄。
4. Docker compose 掛專用持久化目錄；backend／Nginx 唯讀，預建置工具先寫 staging，全部校驗成功後才發布索引及教材清單。不要把 runtime 資產放入容器可丟棄的 writable layer。
5. 部署流程先還原並驗證資產，再啟動服務；提供健康檢查，確認目前教材及抽樣歷史 ID 皆可讀。新機不應只靠 git pull 就假定資產已存在。
6. 雙路徑驗證：新儲存失敗時可切回原 public 目錄；測雲端／匯出舊引用、新教材、ID 舊網址、分享頁、IndexedDB 冷／熱快取及缺失重建。確認後才從 Git 的目前版本取消追蹤完整 JSON。
7. 原歷史結果仍保存於外部儲存，不因目前未引用就刪除。後續再由使用者決定引用核對範圍與清理規則。

## Git 大小與回復限制

取消追蹤只會讓之後的 checkout／新增提交更輕，不會刪除已進入 Git 歷史的大檔，因此舊完整 clone 不會立刻縮小。若要清除歷史，必須另外安排備份、所有協作者重新同步與 force push；本次評估不包含這項授權。

回復至少保留：最後一版完整 Git 提交、原始資產包及其校驗清單、舊 index、Docker／Nginx 設定。舊版程式若仍要求 public/deck-traces，可掛回同一路徑，不必重新編譯歷史 Trace。

## 實作前尚需確認

- 先採專用持久化目錄，還是直接採指定的物件儲存服務。
- 外部備份位置與部署主機可取得的資產來源；不在 repo 內保存憑證。
- 是否只移出完整 Trace JSON，或另評估不可變 asmdeck 歷史包；目前建議先只動 Trace。

選定後先產生資產包與還原報告，最後再批准部署及取消追蹤；在此之前不刪除 repo 內檔案。
