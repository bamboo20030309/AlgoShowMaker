# 範例投影片 Trace 資產

## 檔名與引用

公開結果位於 `algo-vis-backend/public/deck-traces/`，名稱使用投影片檔名加動畫序號，例如：

```text
merge-sort.asmdeck
  → merge-sort-01.json
  → merge-sort-02.json
```

檔案名稱方便維護；投影片仍保存 Trace 內容 ID，不能把可變動的檔名當成結果身分。`index.json` 將 ID 對應到檔名、來源投影片及動畫頁，不將完整結果內嵌到 asmdeck。

前端只在需要動畫時讀取索引與指定檔案，並核對內容雜湊。若分頁保留舊索引、同名結果已更新，最多更新索引重試一次；仍不符就明確回報，不把新結果錯存到舊 ID。已保存的自訂顯示設定仍由投影片個別套用。

舊 `/deck-traces/<ID>.json` 網址由 Express 轉到可讀檔案；Nginx 將這類舊 ID 網址代理至後端，其餘命名檔直接提供。找不到結果仍保留缺失提示與既有重建流程。

## 建置與舊版本

`scripts/build/prebuild-guest-decks.js` 使用 `registerDeckTraces` 寫入命名檔與索引。相同名稱的新結果取代舊結果前，先把舊 ID 對應的結果保留到 legacy 子資料夾；內容 ID 不因檔案搬移而改變。

本輪只搬移檔案，沒有重新編譯或變更 36 份現行動畫的 Trace 內容。另保留 8 份仍被舊投影片引用的結果，共 44 份。

### 2026-11-01 全部現行動畫重建

後續依使用者要求，在獨立服務強制重新分析、編譯與執行 15 份範例的 36 個動畫，更新投影片引用 ID，並同步產生線篩的首幀預覽、完整獨立動畫與程式碼。範例下載網址更新為 `prebuilt-15-trace-refresh`。

重建前的 36 個結果保留為歷史 ID，加上原有 8 份，索引目前共 80 份（現行 36、歷史 44）。歷史結果不覆寫、不重新執行；它們代表當時保存的內容，舊投影片仍可讀取。完整 Trace 仍獨立存放，不嵌入 `.asmdeck`。

強制重建指令在 `algo-vis-backend` 執行：

```powershell
node scripts/build/prebuild-guest-decks.js --base-url http://127.0.0.1:<獨立服務埠> --force
```

`--force` 略過前端重建快取，並將 `forceRecompile: true` 傳至後端，略過執行結果及執行檔快取。逐份執行，每份教材全部成功後才替換投影片檔；任一失敗會保留該份原檔。未指定 `--force` 則沿用一般快取流程。

隔離瀏覽器已核對全部 80 份的內容雜湊、播放器幀數、首／中／末幀跳轉及 IndexedDB 讀回。這是載入與基本導航檢查，不代表每個事件中間過程都經人工畫面驗收。
