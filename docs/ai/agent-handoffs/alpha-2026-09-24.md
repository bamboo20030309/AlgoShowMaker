## 3. 已討論／實作的語法與行為

### 3.1 事件與濃縮幀

- 使用者不需要系統自動摘要演算法，而是希望作者自行編寫濃縮幀。
- 典型作法：`i <= 7` 保留詳細幀，`i > 7` 使用一張濃縮幀，跳過事件動畫並批次畫出多個箭頭／樣式。
- `// @events animate off` 只應關閉事件動畫，不應關掉 style、箭頭、segment 或其他畫面物件的出入場／位移動畫。
- 濃縮幀可用 `@for` 取得後續迴圈實際執行範圍；使用者偏好範圍語法 `[:]`，不使用 `..`。
- 若鄰近多個迴圈都有相同變數名，例如兩個 `j`，無歧義時可自動綁定，有歧義時必須命名迴圈再明確指定。
- while 與 do-while 也應能命名並提供迭代範圍。
- `@style` 支援逗號一次指定多個樣式，例如：
  `// @style isprime[i] highlight,point`

### 3.2 批次迴圈資料與文字陣列

- 使用者希望 `@for j` 可直接套用相鄰／指定的底下迴圈，不必手寫範圍。
- `iteration.last(j)` 表示某次實際迴圈執行最後到達的 `j`，不能隨意綁到其他同名迴圈。
- `@text` 已要求支援直接顯示陣列與範圍，例如：
  - `${prime}`：整個陣列。
  - `${prime[0:iteration.last(j)]}`：指定範圍。
- 文字中的陣列範圍需由目前可見迴圈的迭代資料解析；如果後端尚未整合或服務未重啟，會出現「變數運算式無效」。

### 3.3 automark 與事件設定

- 指令名稱使用 `automark`，不用 `autofix`。
- 期望語法：
  - `@automark isprime`
  - `@automark isprime,prime`
  - `@automark none`
- 可以放在 defaults／preset 中；只選擇哪些陣列顯示自動固定，固定時機仍依最後一次存取判定。
- `automark` 不應受 `@events animate off` 影響。
- 自動固定與迴圈邊界事件設定要保存到 `.asm-view` 的 `studio.eventSettings`，重新載入後仍生效。

### 3.4 Segment Tree renderer 通用能力

已討論並實作／採用的主要語法：

```cpp
// @frame tree render heap with range(1,Tsize-1), fields(tree,lazy,sets), hide(lazy=0,sets=LM), format(lazy=signed,sets=assign)
```

- `with` 專門提供 renderer 額外顯示選項。
- 選項包含：`range(...)`、`fields(...)`、`hide(...)`、`separator(...)`、`format(...)`。
- `fields(tree,lazy,sets)` 將相同索引的多個陣列值合併在同一格，但 instrumenter 仍分別追蹤來源陣列。
- `hide(lazy=0,sets=LM)` 每幀重新計算；隱藏後不能留下空欄位或多餘分隔符。
- 預設分隔符是逗號。
- `format(lazy=signed,sets=assign)`：lazy 顯示為 `+3`／`-2`，sets 顯示為 `=5`，避免單看數字混淆。
- tree 本身的數值相加動畫只能搬動 tree 欄位值，不能把合併格中的 `=13`、`+3` 一起搬走。
- pair／tuple 是單一陣列的一個格子，`pair<int,int>` 預設顯示 `a,b`，不顯示括號；可用 `hide(second=0)` 隱藏特定成員。

### 3.5 標準線段樹 renderer

- 新 renderer 名稱：`render segment_tree`。
- 標準用法：

```cpp
// @object tree render segment_tree with range(1,n)
```

- `range(1,n)` 同時提供 domain 與 root 推導所需資訊，不另外要求 `domain`、`root`、`unit`。
- 預設單位寬 40px，index 區高度約 12px。
- index 開啟時，value 字體應一致；葉節點 interval 也必須顯示括號，例如 `[7]`。
- interval 靠右，index 置中；interval 字體比 value 小約 2px，兩位數不能與 index 重疊。
- 標準 n 非 2 次方時，節點寬度反映代表區間長度；不強制葉節點對齊，父節點下方要對應左右子節點。
- `gap`：
  - 垂直 gap 拉開層距；大於 0 時畫連線，等於 0 時不畫線。
  - 水平 gap 除了拉開同層格子，也會增加 heap／segment_tree 節點寬度：長度 3、單位 40、gap 10 時寬度為 `3*40 + (3-1)*10 = 140`。
  - 一般陣列只增加格子間距，不拉長格子本身。
  - 範例盡量 gap=0，保持格子貼齊。

### 3.6 segment、background 與樣式層

- 格子內區段語法：

```cpp
// @segment tree[node][L:R] color AV_green as active_range
```

- 第一層索引選定 heap／segment_tree 格子，第二層 `[L:R]` 是該格內部區段，端點都包含。
- 邊界規則：`L > R` 不顯示；左界小於 0 或右界超過局部範圍時裁切；多個 segment 可重疊，後寫的在上層。
- `split(now)` 每次依根範圍與目前節點重新計算拆分後應顯示在哪些格子，不是永久儲存 segment 集合。
- `split(now,after)` 表示完成目前節點後的拆分狀態，用於將當前完成的部分移除並保留其他待處理區段。
- 使用者最後決定：長期保存的 lazy／set 視覺狀態使用既有 `background`，不要再做重複的 `style segment` 功能。
- 當前操作的 segment 可做半格／局部顯示；長期保存的 background 顯示整格。
- background 使用同色不透明版本，segment 使用半透明色。
- `AV_orange` 改為與其他顏色一致的半透明調色；`rgba(231,144,255,0.65)` 命名為 `AV_magenta`。
- index 的塗色應與 value 同步。
- background 出現要有過渡動畫；從半透明 segment 轉成不透明 background 時，應先讓 background 在底層出現，再讓 segment 退場，避免白色閃爍。
- segment 左右界各畫 1px 灰色虛線。
- split segment 下降時入場由上往下淡入，出場由上往下淡出；回溯幀原先討論後，使用者決定 segment 不必回來，但後續標準線段樹範例又要求回溯時插入數值合併幀，並在需要的情境加 `split(now,after)`。以最新範例為準。

### 3.7 賦值與運算動畫

- `sum += tree[now]`：tree 格子內的數字移動到 sum；到達目的地的瞬間消失，立即更新 sum，不應停留。
- 全域 sum 若跨幀持續存在，不應每幀重新播放整個物件的出入場動畫。
- `tree[i] = tree[left] + tree[right]`：兩個來源格子的純 tree 數字同時移向目標，在抵達瞬間消失並更新目標數字。
- 合併格中的 lazy／sets 欄位不能跟著 tree 數字移動。

## 4. Segment Tree 教學內容的已確認敘事

### 標準版

- 主線先介紹標準遞迴線段樹：從根 `[1:n]` 往下分裂，葉節點可能深淺不一，再由下往上合併。
- 標準一維陣列實作使用 `now*2`、`now*2+1`。
- 為何常配置 `4*n`：實際節點只有 `2n-1`，但 heap 編號在 n 非 2 次方時會產生洞。令 `P=2^ceil(log2 n)`，最大索引小於 `2P`，而 `P<2n`，所以 `4n` 是安全上界。
- n=10 的標準樹有 19 個實際節點，但最大使用索引可能到 25，不能只配置 20 格。
- 標準版建樹、區間 add／set／query 都有動畫。

### 齊頭式葉節點／迭代建樹版

- 不稱為「你的版本」，直接稱「迭代建樹」「固定葉層」或「齊頭式葉節點」。
- 由葉層開始排，所有葉節點一定在同一層，不會像標準遞迴線段樹那樣深淺不一。
- n=10 時取 P=16，輸入放在固定葉層，剩餘葉子補單位元素；區間和的單位元素是 0。
- 建樹是迭代式由底向上，但區間修改與查詢仍使用遞迴；不能宣稱整套實作都是迭代式。
- 迭代建樹動畫也改用 `render segment_tree`，並使用 `@object tree[i]` 把迴圈變數標籤綁到目前格子。

### 共通比較

- 建樹 O(n)。
- 單點修改 O(log n)。
- lazy 區間修改與區間查詢 O(log n)。
- 陣列儲存皆為 O(n)，遞迴版另有 O(log n) 呼叫堆疊。
- 比較的是配置策略；不能把 `4n` 說成實際節點數，也不能把固定葉層說成絕對最省記憶體。

## 6. `.asmdeck` 檔案格式與製作方式

- 檔案開頭是 9 bytes：`ASMDECK1\n`。
- 後面是 gzip 壓縮的 JSON：`{ manifest, body }`。
- `body` 包含 `{ deck, assets }`。
- `manifest.contentHash` 必須是 JavaScript `JSON.stringify(body)` 的 SHA-256；Python 的浮點序列化可能不同，最好用 Node 計算。
- `manifest` 常見欄位：

```json
{
  "format": "AlgoShowMaker.asmdeck",
  "packageVersion": 1,
  "engineVersion": "8/1",
  "exportedAt": "ISO timestamp",
  "contentHash": "sha256",
  "assetHashes": []
}
```

- 投影片 native canvas 為 1280×720，Fabric.js 5.3.0。
- code widget 使用 `type: "code"`、`language: "cpp"`、`showLineNumbers: true`。
- structure widget 使用 `type: "structure"`、`structureMode: "segment_tree"`、`indexMode: 1`、`indexBase: 1`。
- 編輯投影片後，要用 `ASMDeck.decode()` 實際匯入驗證雜湊與結構。
- 動畫要呼叫 `/trace/analyze` 與 `/compile` 產生追蹤；測試使用獨立隨機埠與 headless Edge，不操作使用者分頁。
- 投影片動畫實際驗證至少包含：編譯無錯誤、trace 有幀、查詢輸出正確、播放器可按下一步與跳到最後、代表頁截圖確認版面。

## 8. 已知易踩坑

- 使用者可能直接在上一版 `.asmdeck` 中修改動畫程式或 input。每次收到新附件，都要以附件為準重新解包；不要拿 workspace 的舊 JSON 覆蓋新修改。
- 更新動畫前一頁的文字時，必須從最新 `animation.input` 模擬操作並算出答案；不要沿用舊的 27、45、36。本次最新是 44、65、51。
- `point` 若可由變數綁定表達，優先用 `@object tree[now]` 或 `@object tree[i]`，不要再加抽象 point 標記。
- 迭代固定葉層版若改成 `render segment_tree`，要確認 range 表示 domain 長度還是 storage index；不要只做字串替換而導致葉數錯誤。
- n=10 的標準 `segment_tree` 使用 heap 編號時有索引洞，structure 靜態圖若只靠連續 content 推導 domain，可能漏掉 storage 24、25。之前曾用額外 Fabric 物件補葉節點；接手後若重新生成，需實際截圖檢查完整 10 片葉子。
- `@events animate off` 不應關閉 automark、style、arrow 或 segment 動畫。
- style 不應殘留上一幀；每幀的顯示狀態應由該幀重新計算，而非沿用前一幀 transient style。
- lazy／sets 欄位顯示、hide 與 format 都必須在每幀重新計算；被隱藏的欄位不能留下逗號。
- 回溯時 background／segment 轉換曾出現短暫消失，要檢查同一時間的層級、入場與退場排程。
- 3101 重新整理不一定代表後端已重啟；語法支援在後端時必須確認 PID 與程式版本。

4. 若接續程式功能，從最新 integration 建立／更新含 alpha 的獨立分支，先調查現況再修改。
5. 小驗證只跑受影響 parser／renderer／動畫範例；主代理完成整合後再跑大驗證。
6. 程式更新後 commit、push、重啟自己的 3101 並確認 `/trace/analyze` 與前端版本；投影片-only 任務依使用者要求直接回傳 `.asmdeck`。

## 10. 交接時最重要的三件事

1. **以最新附件與最新使用者訊息為準。** 使用者會直接修改動畫程式與 input，舊範例數字很容易失效。
2. **語法與畫面狀態分層清楚。** event、style、automark、segment、background、欄位格式與運算動畫互不應誤傷。
3. **實際播放驗證。** parser 通過不代表畫面正確；至少檢查代表幀、最後結果、出入場、回溯與播放器操作。
