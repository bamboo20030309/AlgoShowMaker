# 跨幀事件間隔修正

## 原因

事件設定滑桿及保存值正常；buildEventTimeline 只在同一幀第二個以後的事件前加入 gapMs。播放器每幀重新建立計畫，完成後直接接下一幀，導致跨幀遺失間隔。獨立實測 600 ms 設定：幀內約 600 ms，跨幀約 10 ms。

## 修正

在仍有下一幀、向前播放且本幀有事件時，正式播放計畫增加 event-gap 等待階段。等待從事件結束開始，與既有幀內等待共用 gapMs；計畫完成後才允許下一幀接續。沿用原有倍速、暫停、取消時鐘，不另外建立 setTimeout。0 ms、不含事件、反向、直接跳幀及最後一幀不增加尾端等待；原有事件動畫時長及提交點不變。

## 驗證

- V2 局部，使用獨立服務、瀏覽器及公開測試程式，未操作使用者分頁。
- event-gap.browser.test.js：從介面設定 600 ms，固定答案核對幀內起訖差為 600 ms，計畫等待階段為 600 ms，實際跨幀確實停頓；缺欄位與明確 0 ms 無等待、IndexedDB 保存重開、最終 a=3、最後一幀無多餘等待。初次重現失敗後修復，未放寬斷言。
- event-motion-policy.test.js：3 項基本時長／同值賦值規則通過。
- event-playback-control.browser.test.js：既有暫停、繼續及保留同一播放完成承諾的局部驗證通過。
- JS 語法、差異檢查；更新 tween、投影片內嵌與頁面快取版本。
- 交付 intergration；核對來源後只重啟 3100，確認 HTTP 與腳本一致並推送。未合併 main、未發布 release。
