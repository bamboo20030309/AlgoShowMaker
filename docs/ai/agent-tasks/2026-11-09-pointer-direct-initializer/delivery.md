# 指標初始化直接在目標入場

## 修改與規則

指標宣告初始化（例如 `int min_idx = i;`）不再因來源可見而採「未綁定標籤入場→複製賦值→跨格移動」。改為直接在初始化後的目標格子旁入場，包含可見變數、常數與隱藏來源。事件原始資料仍保留 declare／assign，播放器仍以合併初始化處理；沒有新增必填欄位。

普通數值／陣列的可見來源初始化仍保留原本複製，後續 `min_idx = j;`／`i=4;` 等重新賦值照常位移，同值賦值也照常播放。入場仍為 220ms；同格需要讓位時保留原有 80ms 等待，因此該槽位為 300ms，沒有另加賦值飛行時間。

只修改播放器判斷與前端快取版本，不更動生成 Trace 的來源／引擎指紋。現有 Trace 載入新版播放器即可使用，不重跑全部範例。

## 驗證

- `initializer-visibility.browser.test.js` 通過新資料、序列化儲存重開及缺少 semantics／declarationInitializer 的舊資料模式；固定答案核對 k 在目標位置入場、後續 i 連續位移、箭頭跟隨、同值賦值與中途取消，並保留一般值／陣列初始化複製檢查。
- 新增選擇排序公開 Trace 的實際 SVG 案例：min_idx 在 1／4 倍速從可見起 x 即維持 arr[0] 旁的最終位置，不從外側移入。
- 既有快速排序退場、宣告／跨格移動／純顯示移除、延後替換入場案例通過。矩陣退場案例第一次併行採樣未捕捉到短淡出區段，獨立重跑原斷言通過，未修改容許值或路徑。
- 初始化測試原先把黃色反白開始視為物件入場，期待隱藏文字已有數值；以修改前初始化規則也重現同一個 literal 空字串失敗。改為核對實際 SVG 第一次可見時的數值，仍使用固定 9／全零／[1,2,3] 答案，未修改產品顯示來迎合測試。
