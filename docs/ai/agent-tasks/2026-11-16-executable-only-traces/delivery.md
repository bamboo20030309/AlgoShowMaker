# 只保存執行檔，Trace 僅留本次頁面記憶體

## 任務與範圍

依 2026-11-16 使用者要求，刪除全部結果快取（包含 Git 已追蹤的歷史 Trace），保留原生執行檔；投影片載入後由前往後逐份重新執行。工作分支 intergration；不合併 main、不發布 Release、不改寫 Git 歷史。

## 交付

- 移除 `public/deck-traces` 295 個檔案（954,232,682 bytes）及預設動畫 8 個 `.asmtrace` 檔（1,609,959 bytes）。`.gitignore` 禁止再次加入這些結果。
- 15 份現行公開教材、36 個動畫及歷史封裝轉為來源／輸入／顯示設定／執行檔 ID；36 個現行動畫已順序重跑成功並預熱執行檔。
- 前端不讀寫結果 IndexedDB：草稿 schema 2 清空 traces store；兩個舊結果資料庫於開啟介面時刪除。保留草稿、圖片、明確 false、自訂設定與原程式。
- 任何載入入口都使用配方；準備順序為各水平頁內由上往下，從第一個動畫開始。跳頁不插隊；失敗保留來源、繼續處理後續動畫。
- 手動 RUN 的執行檔 ID 經 detach／儲存／匯出保留。儲存與匯出不要求動畫先執行成功。
- 後端停用結果快取，仍驗證來源、編譯器與插樁所得執行檔鍵；不接受上傳任意原生程式。每次執行沿用原有佇列與資源上限。
- 非同步回應只作短期傳輸：全部合併觀看者收到後清除，未下載回應預設兩分鐘到期。進行中合併不等於保存完成結果。
- 舊 public Trace URL 與受權限保護的結果端點回傳 410；完整 Trace 上傳被拒絕。
- 雲端實際遷移 22 份投影片，0 失敗。獨立盤點：保存結果的投影片 0、包含 Trace frames 的結果資源 0。
- 第一輪線上遷移使上述 22 份投影片的 `updated_at` 成為遷移時間，未保留遷移前的該時間欄位。已告知使用者；後續／測試中的遷移保留原編輯時間。內容與來源保留。

## 驗證與標準答案

- 原生執行檔：同一程式先輸入 7、再輸入 9；標準答案為輸出 7／9，第二次 executable HIT、trace DISABLED，結果目錄為空。
- 共用工作：兩個獨立觀看者同時送相同程式，兩人都收到 21，全部收到後傳輸檔歸零；保持授權隔離。
- 投影片順序：直接進第三個動畫仍依序送出 1、2、3；第二個故意編譯失敗，第三個仍完成；重新整理再次依 1、2、3 執行，沒有舊 Trace 請求。
- 線篩預設頁：兩次開啟各送一份執行工作、不下載 `.asmtrace`／`deck-traces`，兩次均 ready，無 pageerror。
- 新舊資料：無新欄位的舊草稿與引用遷移，來源／false／0／自訂顏色保留；儲存重開不含 Trace；手動 RUN 的 executable ID 保留。
- 雲端分塊：圖片完整往返、續傳、跨 deck 隔離、衝突與失敗不替換原快照、Unicode 邊界；新政策不再要求下載或上傳舊結果。
- 封裝：全部公開及歷史檔可解析、目前清單網址雜湊符合實際位元組；36 份來源及 executable ID 存在，無結果 payload。
- 測試 fixture 不再讀 Git Trace，改以隔離服務即時執行後只留測試行程記憶體；堆積跨呼叫／遞迴可見性的實際瀏覽器驗證通過。
- 相關 storage、cloud、archive、artifact-cache、compile-job-registry、default 與局部瀏覽器檢查通過；不宣稱完整全站 regression。沒有放寬動畫答案。
