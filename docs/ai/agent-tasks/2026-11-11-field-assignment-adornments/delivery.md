# 同欄覆蓋值遮罩與格式符號先行

## 問題與修正

使用者回報同一線段樹第24→25幀：tree的舊值2與就地顯示的新結果5重疊；lazy的新值出現時，逗號與正號還沒出現。前次修正只處理欄位錨點，沒有完整處理這兩個播放規則。

- createLiteralAssignmentTransfer明確回傳coversTarget。不可見來源也會走這個就地數字回退，所以不能只用source.literal判斷是否遮住舊值。現在覆蓋數字顯示時遮住同欄舊數字，準備階段仍保留舊值，提交後恢復正式文字；不提前改正式值。
- 欄位量測拆出格式前綴與數字，數字的落點對準前綴後的字元，字級與基線仍繼承實際欄位。
- 新欄位的逗號與`+`／`=`以臨時tspan在準備階段先呈現。覆蓋數字在準備完成後才顯示，既有欄位的前綴則只在舊文字被遮住時接手，避免符號重複。
- 提交時同一更新清除臨時符號並恢復完整格式文字。取消／清理也移除臨時節點。沒有新增事件或延長原時序。

## 固定答案與證據

multi-field-replay.browser.test.js增加可見性與臨時符號斷言：

- tree的覆蓋數字顯示期間，舊tree文字不可見。
- lazy數字之前已存在逗號與正號；數字顯示期間兩者保持可見。
- 數字落點比對穩定渲染中的實際數字字元Range，而非整個`+3`字串中心；基線與字級一致。
- 正式值仍依2→5、隱藏lazy→+3順序提交，提交及JSON重開後沒有臨時符號；原欄位位置、逗號案例及同幀隱藏測試保留。
- 同時檢查新編譯及公開既有Trace，1／4倍速。

19fc6ed播放器以相同測試可重現舊新數字重疊的失敗，修正版通過。實際隔離畫面也核對tree只有一個5，以及lazy由`5,+`再到`5,+3`的呈現。

多欄位案例與既有push_back複製、binary／compound算術兩項，共3項不同定向測試通過。語法與差異檢查通過；未執行完整V3。畫面、TAP與暫存探針位於被忽略的test-results，不提交。
