# 快速排序 Trace 程式碼座標與快取修正

## 問題與原因

- 公開快速排序兩份動畫的事件位置使用 LF 原始碼，但 `ASMDeck.applyPresentation` 又以含 CRLF 的編輯文字覆寫 `sourceCode`。
- 以第一份動畫為例，`main` 的事件來源原本是 `int main() {`，依覆寫後文字的位置取出卻變成 ` - 1);`；事件行號本身沒有變，但絕對字元座標已錯位。
- 來源指紋會正規化換行，所以舊檢查仍回傳 current；單純重新 RUN 後仍會被相同封裝流程弄壞。

## 修正

- 呈現設定只套用 view；保留編譯結果的 LF `sourceCode` 與原本 provenance，不再替換來源、重新簽發來源指紋。
- 共用狀態檢查將 CRLF 覆寫、或與編輯內容語意來源不同的 Trace 判定為 outdated，接上既有紅點、禁止播放舊結果與自動重建流程。
- 編輯器文字可以保留 CRLF，這本身不要求重跑；必須保持 LF 的是事件座標所對應的 Trace 原始碼。
- 首頁、投影片、動畫頁與內嵌編輯器更新腳本版本。
- 預建工具增加獨立座標核實：依實際文字換行位置，檢查事件 from/to 是否符合 line/column 與 endLine/endColumn。沒有使用播放計畫產生答案。
- 15 份公開教材、36 份動畫全部重建並核實後才切換清單；保留舊 ID，不刪除使用者內容。

## 限制

綠點表示來源與生成版本可用，不代表系統能自動辨識所有動畫邏輯錯誤。本次補上具體的來源座標錯位缺口，公開素材額外核實文字位置。
