# 指標完成當幀出界更新後才退場

## 行為與原因

合併排序第 10→11 幀的來源指標，在 push_back 完成後仍有 i++／j++。目的畫面未保留出界指標，先前只檢查目的畫面的可見指標，漏掉這個更新事件。

現在同時核對來源、目的畫面的指標與 runtime lifetime，保留更新的正式位移時段。沿用原事件間隔，先完成 push_back，再等待間隔，再播放 520ms 指標位移，出界後以 220ms 退場。標籤與箭頭一起移動；不以教材名稱或幀號寫特例。

舊指標的定位同時使用前後畫面的幾何資料，避免目的畫面沒有格子錨點就略過移動。退場尾段納入對外播放計畫的總時間，間隔設為 0 時也必須等退場結束，不能提前切換下一幀。

## 驗證

- merge-push-handoff.browser.test.js：兩組公開合併排序、i／j、1／2 倍速、20／37ms 畫面更新、0／500ms 間隔，共 16 組通過。使用手寫時間答案與實際 SVG 的座標、透明度核對，包含移動過程至少三個不同位置、移動完成前不退場、提交後目標格子持續可見。
- initializer-visibility.browser.test.js：初始化與指標連續位移通過。
- heap-marker-assignment.integration.test.js 的 same-name markers 案例：同名指標依各自 runtime lifetime 接收事件，通過。
- 語法與差異檢查；未執行全量 regression。不改 Trace 格式或 C++ 插樁，既有 Trace 不需重新編譯。
