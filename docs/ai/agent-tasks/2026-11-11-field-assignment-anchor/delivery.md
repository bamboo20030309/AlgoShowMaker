# 多欄位賦值的欄位錨點

## 重現與根因

使用者再次指出線段樹第24→25幀，並說明「有逗點的數字本來靠左，賦值卻從格子中間進入，原數字也突然回到中間」。上一輪只確認數值、欄位存在與提交順序，漏掉特效的落點及整串文字的置中行為。

同格fields以一個置中的text包含多個tspan；舊賦值沒有獨立欄位錨點，修改其中一段或隱藏其他段會重新計算整列置中。特效又從父text的x/y與直接屬性取得座標、字級，忽略tspan實際位置及繼承的字型，導致落點偏到格子中央、基線與字級不符。

## 修改

- createFieldAssignmentLayout以事件當下的列狀態，暫時測量本次提交後的欄位位置，立即還原資料；不使用幀末未來值作為正式內容。
- 各tspan暫時固定獨立x錨點，改字不再重新置中兄弟欄位。需要新增／刪除欄位時，在原ASSIGN_TIMING.frame準備階段平順騰位，不新增事件或延長時序。
- 數字傳遞對準目的欄位，數字進入前先完成騰位；隱藏目標也有本次事件的量測位置。特效字型與基線取實際繼承值，不用14px／整格中心回退。
- 特效結束移除暫時錨點，回到相同幾何的自然排版；格式、分隔符、hide與事件提交規則保留。
