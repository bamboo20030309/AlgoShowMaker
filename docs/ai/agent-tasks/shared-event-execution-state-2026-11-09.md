# 共用事件執行狀態

## 需求與範圍

依使用者確認，指標位置、格子綁定與比較跟隨共用事件當下狀態，並檢查其他混用幀末狀態的路徑。維持 intergration，不合併 main、不發布。

## 稽核與修改

| 路徑 | 原本的缺口 | 現在的資料來源 |
|---|---|---|
| 比較指標跟隨 | 邏輯配對失敗就比對 SVG 節點，可能誤跟後續交換的實體節點 | 事件前狀態、runtime identity／lifetime 與邏輯索引；保留節點用明確 snapshot cell key |
| 指標位移與重排 | 只將被修改的變數填入 locals，其餘運算式變數可能讀到幀末值 | 共用完整事件前／後狀態；關閉動畫的寫入仍提交 |
| 指標入場與退場前位移 | 各自掃描 payload before，與正常移動使用不同解析方法 | 共用執行狀態；幀初重排使用第一個事件之前的狀態 |
| 賦值／算式／來源格子 | 部分來源查詢沿用 capture frame | effect 工廠收到事件前的 frame；呈現節點由同事件的 visual binding 決定 |
| min/max 選值 | 未同步比較提示的指標位置，也沒有共用跟隨解析 | 共用事件狀態、位置校正、指標綁定；提示同步後才顯示 |
| 讀取強調 | 沿用 capture frame 找來源 | 所屬事件之前的狀態，合併初始化時使用初始化事件 |
| 序列、位元效果與泛用事件 | 部分工廠／預先 staging 查詢 capture frame | 共用事件前 frame；陣列存在與長度納入邏輯狀態 |
| 矩陣指標 | 二維座標缺少各維度的原始運算式 | renderer 補上列／欄運算式 metadata，解析每一維當下值；舊 Trace 載入時重新生成，不要求持久化新欄位 |

`createExecutionContext` 使用同一份事件 mutation 建立唯讀查詢，與播放時的顯示提交分開。停用的動畫可以沒有時間槽，但不能因此提前影響前面的邏輯值。Frame 與保存的 Trace 不會被改寫。

特別區分 `@exit` 與 scope-exit；前者只隱藏視圖，不會使下一輪 i++ 失效。陣列 alias 共用實際內容與長度；reference 宣告前不能清空其已存在的來源。字串索引寫入保留其他字元。

## 保留的用途

- 最終 DOM／版面可預先建立；交換仍需要邏輯格子到實體 SVG 的映射。這些是畫面投影，不是變數值、指向或來源的判斷依據。
- camera與keep仍依幀或快照語意；2026-11-11已依事件跟隨稽核調整：文字運算式與箭頭動態索引接共用檢查點，style採C2，只有含執行變數的索引／範圍選取跟隨事件提交，不在每次內部狀態改變都執行整套指令。詳見事件規格的「作者指令依賴跟隨」。
- 舊格式的單次序列 mutation 仍有大小與次數核實的前後快照相容路徑；不對多次變動猜中間值。

## 驗證

V2；使用獨立服務與瀏覽器，未操作使用者分頁。

- 新增 `execution-state.test.js`：7 個固定答案案例，涵蓋多變數索引、關閉動畫仍提交、identity／lifetime、矩陣座標、visual-exit／scope-exit、序列 size 與 alias、字元更新、reference 入場。核對常數答案，未使用播放計畫生成預期值。
- 新增 `execution-state.browser.test.js`：複合指標 `i+k` 必須在稍後 k=2 前指向 1，且與 a[i+k] 賦值位置一致；min 選值提示必須出現在前一事件已更新的 i 位置。兩項通過。
- 快速排序無關指標、冒泡比較指標：1 倍／4 倍與保存資料驗證通過。
- 遞迴保留節點比較、push_back 提交接續 i++、內嵌 postfix／prefix 順序：三項通過。
- 矩陣列欄與顏色保存、插入排序宣告複製、選擇排序跨輪指標生命週期：三項通過。
- `unresolved-markers.test.js` 相關六項通過。補齊測試對 tween 的獨立載入，將依賴舊 partial-locals API 的 mock 改成真實 resolver，固定答案不變。
- 選擇排序初次驗證發現 i 在 @exit 後失去邏輯存在；修正為視圖退場與 C++ 生命週期分開後重跑通過。
- 讀取強調的開關／純紅色／自訂色／舊物件／明確關閉／儲存重開通過。原測試固定 120 ms 採樣，在修改前 HEAD 與新播放器皆因程式反白等待而失敗；改為觀察完整所屬事件，保留原數量與顏色標準，另核實 owner event ID 與結束清理。
- 相關 JS 語法、差異與前端版本核實。未執行完整 V3。
- 本次只改播放器／呈現 adapter，生成指紋維持不變，公開預建清單仍全部匹配，不重跑未受影響的 C++ Trace。
- 未逐一跑完所有 render×event 組合，亦未將整個播放器改寫為逐事件重新建立 DOM；這次針對執行狀態的共用入口及已識別的呼叫路徑修正。

## 相容性

新編譯資料、既有公開 Trace、缺少 captureOrder／afterCapture 的保存資料、IndexedDB 儲存重開、自訂與明確關閉設定皆使用相關既有案例核實。新增矩陣運算式欄位只存在於重新繪製的 DOM metadata，不改投影片封裝格式。
