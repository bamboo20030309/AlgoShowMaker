# 指標事件排版交付紀錄

## 問題與修正

快速排序一般例第 18→19 幀，i 原本在 j 退場事件前就套用目的幀的單指標布局。原因是比較與指標位移雖已使用事件狀態，幀級 REFLOW 仍提前讀取最後的群組成員。

- 入場、賦值／位移、scope-exit 與視覺退場，統一由當下事件狀態決定群組成員與槽位。
- 退場複本仍參與退場前的排版；開始淡出才同步補位，不再疊加舊版 assignment／peer 重排。
- 只改顯示的增減用暫時視覺時鐘；等待退場 barrier 的新指標，入場前不占位。這些時鐘不寫成假 C++ 事件。
- 矩陣列／欄地址與二維格子地址可進入共同排版；缺失二維格子不套用一維外推。
- 延後入場的群組補位納入共同播放完成計畫，保留既有一般讓位 300ms、退場 220ms 與原本指標位移時間。
- 前端版本為 tween 326、投影片 326、嵌入 runtime 81；Trace 產生語意與指紋未改，無須重跑全部範例 Trace。

## 固定答案與驗證

使用獨立服務與隔離 Edge 瀏覽器，不操作使用者分頁或投影片。

`tests/pointer-event-reflow.browser.test.js` 的四個案例檢查實際 SVG 標籤座標與從標籤到祖先的有效透明度，沒有用播放計畫產生預期座標：

1. 快速排序 18→19 幀，1／4 倍速；j 完全可見時 i 的 x 保持不變，j 淡出時 i 才移動，最終只剩 i。
2. 同格指標宣告、跨格移動、純顯示移除；讓位不能早於對應入場／移動／淡出。
3. 矩陣列指標退場；存續指標只在舊指標淡出期間補位。
4. 舊 j 退場後新 k 才入場；j 淡出且 k 尚未可見期間 i 先回中間，k 入場後恢復雙指標布局。

另外執行 `tests/execution-state.test.js` 七項與 `tests/selection-pointer-lifecycle.browser.test.js` 一項。合計 12 項通過，選擇排序涵蓋新資料、缺少 captureOrder 的舊資料、1／4 倍速、反向、重播及重新套用資料。更新完成計畫後，再重驗直接受影響的四個群組排版案例。

語法與差異檢查通過。未執行完整 V3，也不宣稱所有 render × 事件組合均已覆蓋。規則同步至 `docs/reference/event-contracts.md` 與 `docs/reference/trace-behavior-rules.md` 的 T22。
