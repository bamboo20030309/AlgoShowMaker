# 遞迴指標參數與同名變數

## 問題

使用者提供的標準線段樹，輸入10個值及5筆操作，第一次query的第3→4幀由節點2遞迴至節點4。Trace正確記錄query的now=4，但動畫最後跑到左側x=-90；正確節點4中心是x=410。

事件狀態已依變數ID記錄值，pointerTarget卻將所有純量按名稱填入locals。push(now,l,r)呼叫結束後的push:now空值覆蓋query:now，讓指標被誤判無可定位目標。問題在播放端名稱解析，不在C++參數傳遞或Trace生成。

## 修改

指標運算優先從data-trace-source-variable-ids綁定的宣告ID取得事件當下值；保留既有其他運算環境，不以幀終值或DOM位置回推。支援舊Trace已有的來源ID，不增加資料欄位、不改初始化及事件時序。

獨立頁、投影片runtime及動畫編輯器同步快取版本trace-336、slides-339、trace-runtime-94。此次無需重新生成Trace。

## 固定答案與驗證

recursive-parameter-pointer.browser.test.js使用附件原始碼與指定輸入，以及既有範例儲存Trace，分別以1／4倍速驗證：

- 確實存在push:now退場及query:now宣告值4。
- 第3幀指向節點2；播放時位置維持節點2至4之間，且實際有中途位移。
- 最終落在節點4中心；返回第3幀與重開第4幀均正確。
- 無瀏覽器錯誤。

相同測試以修改前68d18c7播放器重驗，會因指標跑到左側而失敗；修正版通過，未放寬標準。新案例1項，相關堆積指標1項、內嵌指標1項及指標模型8項，合計11項通過；語法與差異檢查通過，未執行完整V3。
