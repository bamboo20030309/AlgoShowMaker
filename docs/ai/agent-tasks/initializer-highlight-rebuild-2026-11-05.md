# 初始化反白在程式碼面板重建後拆開

## 使用者回報與核實界線

使用者仍看到合併排序第 26 幀的黃色反白先後拆成 i=L、型別及 j=mid+1，且認為間隔很短。唯讀核對使用者頁面，已載入 runtime-64、tween trace-316、presenter code-35，不能歸因於舊版本。

隔離環境用實際「下一步」及原生時鐘播放第 25→26 幀，未重建面板時，完整反白正常。該份公開教材的 gapMs=500，在預設 1.2 倍下實際約 417ms；兩次初始化各 220ms，在該倍速下約 183ms。這份證據不能證明使用者當時的設定或全部更新路徑都正常。

## 重現的漏修路徑

前輪只在 slot 的 start 通知讀取反白，漏掉事件中途的畫面。新增測試在開始後 50ms 重建同一程式碼面板：原本完整的 int i=L 變成 int i，直到事件結束都未恢復。原因是 renderFrame 清空了當前事件與進度，再用 DOM 的單一 event ID 啟動；這次啟動沒有 slot，於是遺失配對賦值的 activeMemberIds。

這確認了一條可造成黃色反白拆開的產品缺口；未宣稱已直接錄到使用者頁面當時的完整操作。

## 修正

同一 Trace、同一幀且不是明確 stable 跳幀的面板重建，保留當前事件、配對成員、started/completed 與原有排程 ID。沒有新 slot 的同 ID 啟動不再清除配對成員。切到新幀、新 Trace 或明確 stable 呈現仍清空舊狀態。

不重排 tween、不修改事件間隔或初始化動畫時間，不改變舊 Trace 格式。

## 驗證

- `merge-declaration.browser.test.js` 改為每 10ms 檢查整段黃色反白，而不只開始瞬間。
- 涵蓋 0/500ms、1/2 倍、明確關閉初始化賦值、中途重建、有／無 playbackPlan 的重建、間隔期間重建。
- 每個初始化的整段時間都必須維持同一完整反白；兩事件之間的設定空檔不能出現黃色反白。
- 修正前在「中途重建」確實失敗，修正後通過。
- 比較反白、明確關閉比較、缺少比較及條件結果的四項既有小測試通過。
- 原生時鐘、實際下一步的診斷輸出位於忽略的 `test-results/merge-declaration-2026-11-05/native.json`。
