# 缺少目標格子時的箭頭方向

## 原因與修正

Heap 第 40→41 幀的 heapSize 雖已保留並可由 10 移到 9，箭頭仍把當幀不存在的 #10 外推定位座標當作實際端點，因此朝左偏。依使用者要求，找不到實際目標格子時固定垂直向下，等指標完成移入有效格子後恢復正常定位。

指標位移控制器沿自己的事件軌跡保存當下目標鍵；實際格子的存在性只用於判斷箭頭是否使用向下備援，不拿 DOM 回推指標應該指向哪裡。備援旗標同時傳給一般指標與退場副本。既有指標位置、移動時間、生命週期、資料與 Trace 生成指紋不變。

同時補齊 canonical 目標鍵的交接：矩陣 row／column 原本有合法的列／欄錨點，但 renderer 後續的一般 target resolution 會把 row 0 覆蓋成 #0，導致新存在性檢查誤判。現在保留 pointer model 的明確錨點鍵，列／欄錨點以仍存在的矩陣與錨點幾何確認有效，不要求另有格子 SVG。這也是第一次矩陣驗證失敗的原因；未放寬原方向答案。

## 驗證

- `heap-pop-initializer.browser.test.js` 的已儲存 Heap 案例新增實際 SVG 路徑答案：第 10 格消失後的每個採樣，箭頭水平位移絕對值小於 0.001、垂直位移大於 0；既有保留／移動至 heap[9]、初始化、序列化重開及取消檢查保留。修改前確認此答案失敗。
- 定向核對 `pointer-exit-arrow.browser.test.js` 的 Heap 13→14 幀與矩陣 row 退場：正常格子的垂直／側向箭頭維持原方向。
- 隔離服務及瀏覽器，V2 相關案例；未執行完整 V3。同步前端快取版本，不需要重建 Trace。

最後三個定向瀏覽器案例全部通過，包含 Heap 1／4 倍速。修改的 JavaScript 語法及 git diff 差異檢查通過。
