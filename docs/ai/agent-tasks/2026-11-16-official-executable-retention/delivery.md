# 官方執行檔永久保留

## 任務與結果

將現行公開教材與演算法範例的相容執行檔固定保留，排除期限與容量淘汰；使用者程式維持預設 168 小時及容量清理。只接受伺服器控制的來源與有限的追蹤設定，不信任客戶端官方標記。撤下或不相容的舊版本解除固定保留，恢復暫存期限。

不變更原生執行限制、不持久保存 Trace、不改寫 Git 歷史、不合併 main。

## 實作

- official-executables.js 讀取官方清單、來源封裝與 algorithm_sample，辨識程式碼與既有執行檔 ID。
- server.js 在啟動、官方來源變更及編譯時套用保留策略；回應加入 retention 方便核實。
- artifact-cache.js 固定保留時清除 expiresAt；解除時重新設定一般期限，保留狀態與來源資訊寫回磁碟。

## 驗證

- 既有 artifact-cache 12 案通過；新增官方保留 4 案通過：可信來源、有限變體、逾期升級、重新啟動、容量壓力、撤下來源、編譯器不相容及手動保留設定。
- 隔離後端整合 1 案通過：實際 analyze/compile 官方程式、不同輸入命中同一執行檔、私人修改及偽造官方旗標不獲永久保留，暫存期限仍為 168 小時。
- 3100 重啟後 HTTP 200；目前 53 種官方來源，29 份既有官方執行檔已固定保留，全部 expiresAt=null；其餘 50 份快取維持原策略。
- 使用獨立測試服務，未操作使用者分頁或投影片；不跑大型動畫驗證集。

## 部署注意

固定保留作用於該伺服器磁碟；部署容器需保留執行檔快取資料卷。換機或編譯環境改變仍需重編譯。詳細操作見 docs/guides/trace-cache-updates.md。
