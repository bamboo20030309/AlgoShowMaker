## 1. 現況（以 2026-11-16 實際截圖為準）

| 狀態 | 現在的樣子 | 問題 |
|---|---|---|
| 展示模式（view／放映） | 動畫投影片上方有「畫布／輸入／輸出／除錯記錄／語法樹」分頁，下面是播放列與畫布 | 放映時不該出現這些分頁；分頁也佔掉投影片高度 |

| 編輯演算法動畫 | 左側欄最下方有「編輯演算法動畫」按鈕；按下後開浮動視窗（`#algorithmEditorModal`），裡面是 `algorithm.html?asmEmbed=editor`，連程式碼頁頂部列（演算法範例集、我的程式碼、畫布設定、編輯器、GitHub）都在 | 視窗沒有明顯的返回；右上只有「儲存」；內嵌頁的頂部列與投影片無關 |

- RUN：`slides-embed.js` 的 `#slideRunBtn`／`#slideRunError`；父頁 `slides.js` 的 `runSlideAnimation`／`rebuildSlideAnimation`。
- 編輯器：`slides.html` 的 `#algorithmEditorModal`；`slides.js` 的 `openAlgorithmEditor`／`closeAlgorithmEditor`／`saveAlgorithmEditor`。

## 2. 目標
1. **投影片上的動畫只有畫布**：展示與編輯模式都不再有分頁列；播放列只有播放控制，沒有 RUN。
2. **左側編輯欄三個按鈕**：編輯動畫、程式碼、輸入。選到動畫投影片時才出現。
3. **打開時不擠壓畫布**：程式碼與輸入以側邊抽屜顯示，蓋在投影片舞台左側，畫布維持原本大小與構圖。
4. **編輯動畫改成完整頁面**：蓋住整個視窗，左上角有明顯的「← 返回投影片」。
5. **不用手動 RUN**：程式或輸入改過，離開編輯頁或關閉抽屜時自動重新執行。
6. 輸出、除錯記錄、語法樹只在完整編輯頁裡看（右側分頁）。

## 3. 投影片上的動畫（runtime）
- `slides-embed.css`：`body.asm-embed-runtime #subTabs` 改為 `display: none`。`#tab-input`、`#tab-output`、`#tab-debug`、`#tab-syntax-tree` 在 runtime 一律不顯示，`#tab-canvas` 固定顯示。
- 播放列在展示與編輯模式完全相同（⏮ ◀ ⏯ ▶ ⏭、紅點、進度條、時間、幀數、語速），拿掉 RUN 按鈕。
- 紅點保留，代表「動畫需要更新」；自動重新執行時改顯示「更新動畫中…」。
- 錯誤列（`#slideRunError`）保留：自動執行失敗時顯示錯誤摘要、「開啟編輯動畫」與 ×。
- 畫布高度多出原本分頁列的 42px，鏡頭在 iframe 尺寸改變後照常重新取景（沿用 `refreshViewportCamera`）。

## 4. 左側編輯欄
選到動畫投影片時，左側欄最下方顯示「動畫」按鈕組，取代目前單一的「編輯演算法動畫」：

```
┌ 左側編輯欄 ──────┐
│ T  text          │
│ Σ  LaTeX         │
│ …（原有工具）     │
│ ── 動畫 ──────── │
│ {;} 編輯動畫      │  ← 開完整頁面（第 5 節）
│ </> 程式碼        │  ← 開抽屜
│ ⌨  輸入          │  ← 開抽屜
└──────────────────┘
```

- 「編輯動畫」排第一、樣式最醒目（沿用目前的橘色強調）。「程式碼」「輸入」是一般工具按鈕，抽屜開著時呈按下狀態。
- 只有編輯模式有左側欄；展示模式沒有這些按鈕。

### 抽屜（取代「佔據下半部」）
- 按「程式碼」或「輸入」，從左側欄右緣滑出一個抽屜：
  - 寬約 480px（可拖曳調整，記住寬度）、高度同舞台；
  - 蓋在投影片舞台上方，畫布本身不縮放、不移動。
- 同時只開一個抽屜：再按同一個按鈕、按抽屜右上 ×、或按 Esc 會關閉；按另一個按鈕則切換內容。
- 換到別張投影片時，先依第 6 節處理目前的修改；新投影片也是動畫投影片就保留抽屜並顯示它的內容，否則關閉。
- 抽屜內容：
  - **程式碼**：
    - 這張投影片保存的 C++ 原始碼，使用投影片頁已有的 Ace 編輯器，可直接修改；
    - 適合小修改；要調整程式碼框、事件動畫等設定，或看輸出與除錯，用「編輯動畫」；
    - 抽屜頂部有「在編輯動畫中開啟」。
  - **輸入**：等寬字的文字區，這張投影片執行時的 stdin。
- 修改後紅點立刻亮起（動畫需要更新）；關閉抽屜時依第 6 節自動重新執行。
- 資料流：
  - 程式碼與輸入都存在投影片自己的動畫資料（code、input）。抽屜直接讀寫投影片資料，不經過 iframe。
  - 重新執行沿用現有的父頁流程（`runSlideAnimation`／`rebuildSlideAnimation`）。
- 為什麼不用其他作法：
  - 直接放在左側欄裡（展開成一段）：左側欄只有約 170px，程式碼放不下；
  - 浮在畫布上的小視窗：會擋住畫布中央，也要另外處理拖曳與位置記憶；
  - 抽屜貼著左側欄，關掉就恢復原樣，最接近「按左邊按鈕、在左邊看」。

## 5. 編輯動畫：完整頁面
- 取代 `#algorithmEditorModal` 的浮動視窗：改成覆蓋整個視窗的頁面（`position: fixed; inset: 0`），投影片的左側欄、舞台都被蓋住。
- 頁面頂端是投影片自己的標題列，取代內嵌頁的網站頂部列：

```
┌──────────────────────────────────────────────────────────────────────┐
│ [← 返回投影片]  第 10 張：Quick Sort 分區動畫          ● 尚未更新     │
├───────────────┬──────────────────────────────────────────────────────┤
│ 原始碼 程式碼框 事件動畫   C++ ▶RUN │ 畫布 輸入 輸出 除錯記錄 語法樹    │
│ （程式碼頁的左側三標籤）           │ 播放列＋畫布                    │
└───────────────┴──────────────────────────────────────────────────────┘
```

- 「← 返回投影片」放左上角，深底白字、比其他按鈕大；Esc 也能返回（焦點在程式碼編輯器內時除外）。
- 拿掉右上「儲存」：返回時自動存回投影片（第 6 節）。標題列右側只顯示狀態：「已是最新」「尚未更新」「更新中…」「上次執行失敗」。
- 內嵌的 `algorithm.html?asmEmbed=editor`：
  - 隱藏網站頂部列（`#top-bar`）、我的程式碼、範例側欄與手繪工具列；
  - 保留左側三標籤與右側「畫布／輸入／輸出／除錯記錄／語法樹」分頁（輸出、除錯與語法樹只在這裡看）；
  - 頁內 RUN 保留，在編輯頁裡想立刻看結果時使用。
- 返回後回到原本那張投影片的編輯模式，畫布載入最新動畫。
- 開啟時沿用現有 iframe（第二次開不重新載入）；載入中在標題列顯示「正在載入動畫…」。

## 6. 自動重新執行（取代 RUN 按鈕）
判斷依據沿用現有的新鮮度指紋（紅點）：程式碼、輸入或生成設定與目前動畫不一致時，才需要重新執行。

| 時機 | 行為 |
|---|---|
| 按「← 返回投影片」 | 先把編輯頁的程式碼、輸入、`@asm-view` 設定存回投影片。若編輯頁裡已 RUN 過、動畫是最新的，直接套用不重跑；否則關閉編輯頁後在背景重新執行 |
| 關閉「程式碼」或「輸入」抽屜（×、再按一次按鈕、Esc、換投影片） | 有修改才重新執行；打字途中不執行 |
| 只是打開再關閉、沒有修改 | 不執行 |
| 公開範例（本機副本） | 照現行規則只更新本機副本，不回寫官方教材 |

- 執行中：
  - 畫布保留舊動畫，播放列的紅點位置顯示轉圈與「更新動畫中…」；
  - 可以繼續編輯其他投影片；
  - 同一張投影片再次修改時，取消尚未完成的那次，以最新內容重新執行。
- 成功：換成新動畫並停在第 0 幀，紅點熄滅。
- 失敗：
  - 保留原動畫與紅點，畫布上方顯示錯誤摘要、「開啟編輯動畫」與 ×；
  - 不把失敗結果蓋掉舊動畫，也不把未成功的更新標成已儲存（[Trace 快取與階段更新](../../../guides/trace-cache-updates.md)）；
  - 修改本身照常保存，下次修改或手動開啟編輯動畫時可再處理。
- 放映模式不會觸發自動執行；放映時看到的永遠是最後一次成功的動畫。

## 7. 實作步驟（每步各自可驗證）

3. **左側欄按鈕組與抽屜**：編輯動畫、程式碼（Ace）、輸入；關閉抽屜觸發第 2 步。
4. **完整編輯頁**：標題列與返回按鈕、狀態文字、隱藏內嵌頁的網站頂部列與手繪工具列、Esc、返回時存回並依需要重新執行。
5. **手機版**：左側欄在手機上是底部工具；抽屜改為從底部升起的面板，高度約 60%。

## 9. 測試
- runtime：展示與編輯模式都沒有 `#subTabs` 與 RUN；畫布高度等於 iframe 高度扣掉播放列。
- 左側欄：只有動畫投影片顯示三個按鈕；展示模式沒有左側欄。
- 抽屜：
  - 開、關、切換、Esc；換到非動畫投影片時關閉；
  - 畫布的位置與大小在開抽屜前後不變；
  - 修改輸入或程式碼後紅點亮起；關閉抽屜後自動重新執行，紅點熄滅；
  - 沒修改就關閉時不執行。
- 自動重新執行：成功、失敗（保留舊動畫與錯誤列）、執行中再修改（取消舊的）、公開範例本機副本。
- 完整編輯頁：
  - 返回按鈕可見並能回到原投影片；
  - 編輯頁已 RUN 過時返回不重跑；改過但沒 RUN 時返回會重新執行；
  - 內嵌頁沒有網站頂部列與手繪工具列。
- 回歸：`slide-canvas-toolbar`（目前因 `67bf65a` 失效，需先由該改動的負責代理修好；RUN 拿掉後此測試要改寫）、`presentation-mode-selection`、`slide-animation-parity`。

## 10. 風險
- **iframe 高度改變**：拿掉分頁列後，iframe 內畫布高度變大，已存的鏡頭與放映縮放要確認不跳動。
- **自動執行的成本**：編譯需要數秒並占用伺服器；以指紋判斷「真的變了才執行」，並取消過期的執行。快速連續修改多張投影片時，同時最多執行一張，其餘排隊。
- **與 `67bf65a`（執行配方）同時改動**：該提交改了投影片動畫的載入方式；實作前先確認 `runSlideAnimation` 與 runtime 訊息介面在最新統合分支上的樣子。
- **兩個代理共用**：會改動 `slides.js` 的編輯器與 RUN 區段，以及 `slides-embed.*`；實作期間避免其他代理同時修改這些區段。
