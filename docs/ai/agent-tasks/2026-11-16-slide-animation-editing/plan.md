# 2026-11-16-slide-animation-editing：投影片動畫的編輯介面重新規劃（規劃）

## 任務資訊
- 負責代理：Claude（Claude Code 桌面版）
- 分支：`claude/2026-11-16-slide-animation-editing`（從 intergration `75445de` 開出）
- 狀態：規劃，尚未實作；待使用者確認第 8 節。
- 依據：使用者 2026-11-16 指示（四輪）：
  1. 調整整個投影片的動畫編輯介面：
     - 先處理畫布上面的輸入、輸出、RUN 介面；
     - 除錯記錄和語法樹只在編輯模式呈現；
     - 點開輸入、輸出目前是硬生生佔據下半部，要有比較好的作法；
     - 把上面的標籤整排拿掉，移到左邊的編輯欄，展示模式只固定顯示畫布；
     - 「編輯動畫」顯示在左邊按鈕，從浮動視窗改成完整頁面，要有明顯的返回按鈕。
  2. 左側按鈕只留編輯動畫、程式碼、輸入；RUN 改成離開編輯頁就自動重新編譯執行。
  3. 本版依此修正：
     - 輸入直接是編輯欄裡的一個框，省下一個按鈕；
     - 輸入上方放 RUN，或輸入改完後自動重新執行；
     - 這裡的輸入資料與執行結果要和編輯動畫同步；
     - 不需要「程式碼」按鈕：要改程式通常也要看其他資訊，直接在編輯動畫裡改；
     - 只改輸入不必重新編譯，只要重新執行。
  4. 投影片的畫布和編輯動畫的畫布用同一個：
     - 點「編輯動畫」後有完整的過場，讓使用者知道是同一個畫布；
     - 畫布往右靠、展開成完整的右側，左側編輯區一起靠過來。
     - 第 5 節依此改寫。
- 延續：介面改版規劃階段 4 的「展開式編輯器」（示意圖 https://claude.ai/artifact/3V4741nMm3dQa1b8qBvYc7）的過場想法；差別是展開後是完整頁面，並有明顯的返回。
- 投影片檔的內容：依 intergration 的「只保存執行檔」改動，投影片檔只存原始碼、輸入、顯示設定與執行檔 ID，不含執行檔本身，也不含動畫結果；執行檔由伺服器依原始碼編譯並快取，後端不接受上傳原生程式。

## 1. 現況（以 2026-11-16 實際截圖為準）

| 狀態 | 現在的樣子 | 問題 |
|---|---|---|
| 展示模式（view／放映） | 動畫投影片上方有「畫布／輸入／輸出／除錯記錄／語法樹」分頁，下面是播放列與畫布 | 放映時不該出現這些分頁；分頁也佔掉投影片高度 |
| 編輯模式 | 同一排分頁；播放列多了 RUN | 分頁擠在投影片裡，字很小 |
| 編輯模式按「輸入」 | `#tab-input` 直接佔掉投影片下半部，畫布被壓到上半 | 畫布變形、看不到原本的構圖 |
| 編輯演算法動畫 | 左側欄最下方有「編輯演算法動畫」按鈕；按下後開浮動視窗（`#algorithmEditorModal`），裡面是 `algorithm.html?asmEmbed=editor`，連程式碼頁頂部列（演算法範例集、我的程式碼、畫布設定、編輯器、GitHub）都在 | 視窗沒有明顯的返回；右上只有「儲存」；內嵌頁的頂部列與投影片無關 |

相關程式：
- runtime iframe：`algorithm.html?asmEmbed=runtime`；分頁樣式在 `slides-embed.css` 的 `body.asm-embed-runtime #subTabs`。
- RUN：`slides-embed.js` 的 `#slideRunBtn`／`#slideRunError`；父頁 `slides.js` 的 `runSlideAnimation`／`rebuildSlideAnimation`。
- 編輯器：`slides.html` 的 `#algorithmEditorModal`；`slides.js` 的 `openAlgorithmEditor`／`closeAlgorithmEditor`／`saveAlgorithmEditor`。
- 左側欄按鈕：`#algorithmEditSlideBtn`（只在動畫投影片顯示）。
- 編譯快取：`server.js` 以「原始碼＋編譯器＋編譯參數＋引擎」為鍵快取執行檔（`createExecutableKey`，不含輸入）。只改輸入時重新執行會直接重用執行檔，不必重新編譯；快取被清掉時才會退回重新編譯。
- 執行輸出：目前 `runSlideAnimation` 只重建動畫，程式輸出沒有存進投影片資料。

## 2. 目標
1. **投影片上的動畫只有畫布**：展示與編輯模式都不再有分頁列；播放列只有播放控制。
2. **左側編輯欄**：一個「編輯動畫」按鈕，下面直接是「輸入」框與它上方的 RUN。選到動畫投影片時才出現。
3. **只改輸入就只重新執行**：沿用執行檔快取，不重新編譯。
4. **兩邊同步**：左側輸入框和編輯動畫頁讀寫同一份輸入；執行結果（動畫與程式輸出）兩邊看到的一致。
5. **編輯動畫改成完整頁面**：蓋住整個視窗，左上角有明顯的「← 返回投影片」；程式碼、輸出、除錯記錄、語法樹都在這裡看與改。

## 3. 投影片上的動畫（runtime）
- `slides-embed.css`：`body.asm-embed-runtime #subTabs` 改為 `display: none`。`#tab-input`、`#tab-output`、`#tab-debug`、`#tab-syntax-tree` 在 runtime 一律不顯示，`#tab-canvas` 固定顯示。
- 播放列在展示與編輯模式完全相同（⏮ ◀ ⏯ ▶ ⏭、紅點、進度條、時間、幀數、語速）；RUN 從播放列移到左側輸入框上方。
- 紅點保留，代表「動畫需要更新」；執行中改顯示「更新動畫中…」。
- 錯誤列（`#slideRunError`）保留：執行失敗時顯示錯誤摘要、「開啟編輯動畫」與 ×。
- 畫布高度多出原本分頁列的 42px，鏡頭在 iframe 尺寸改變後照常重新取景（沿用 `refreshViewportCamera`）。

## 4. 左側編輯欄
選到動畫投影片時，左側欄最下方顯示「動畫」區塊，取代目前單一的「編輯演算法動畫」：

```
┌ 左側編輯欄 ──────┐
│ T  text          │
│ …（原有工具）     │
│ ── 動畫 ──────── │
│ {;} 編輯動畫      │  ← 開完整頁面（第 5 節）
│ 輸入      [▶ RUN] │
│ ┌──────────────┐ │
│ │10            │ │
│ │5 7 2 1 9 …   │ │  ← 等寬字文字框
│ └──────────────┘ │
│ 已是最新          │  ← 狀態：已是最新／尚未更新／更新中…／執行失敗
└──────────────────┘
```

- 「編輯動畫」排第一、樣式最醒目（沿用目前的橘色強調）。
- 「輸入」框：
  - 這張投影片執行時的 stdin，等寬字；
  - 高度隨左側欄剩餘空間伸展（至少 5 行），內容過多時框內捲動；
  - 不換行，長行可以左右捲動。
- RUN：
  - 在輸入框標題列右側，按下立刻用目前的程式與輸入重新執行；
  - 執行中顯示「執行中…」並暫時停用。
- 自動執行（決定見 Q1）：輸入框有修改、離開輸入框（失去焦點）或停止輸入約 1.5 秒後，自動重新執行。
- 狀態文字：
  - 「已是最新」「尚未更新」「更新中…」「執行失敗：…（開啟編輯動畫）」；
  - 執行成功時顯示程式輸出的第一行摘要，完整輸出在編輯動畫頁的「輸出」分頁。
- 只有編輯模式有左側欄；展示模式沒有這些控制。
- 為什麼不用抽屜：輸入通常只有幾行，左側欄寬度（約 170px）足夠，直接放框可以省下一個按鈕，也不會蓋到畫布。

## 5. 編輯動畫：同一個畫布展開成完整頁面

### 5.1 使用者看到的過場
1. 在編輯模式點左側「編輯動畫」。
2. 投影片上的動畫畫布（連同播放列）往右移並放大，約 400 ms 後成為完整頁面的右側畫布。
3. 同時，左側的「原始碼／程式碼框／事件動畫」編輯區從左邊一起靠過來，填滿左半；頂部的「← 返回投影片」標題列由上方滑入。
4. 動畫停在原本那一幀、保持原本的播放狀態，不重新載入、不閃白。
5. 按「← 返回投影片」或 Esc：反向收回，畫布縮回投影片原位，左側編輯區往左收走。
6. 系統設定「減少動態效果」時直接切換，不播放過場。展示模式沒有這個操作。

### 5.2 版面

```
┌──────────────────────────────────────────────────────────────────────┐
│ [← 返回投影片]  第 10 張：Quick Sort 分區動畫          ● 已是最新     │
├───────────────┬──────────────────────────────────────────────────────┤
│ 原始碼 程式碼框 事件動畫   C++ ▶RUN │ 畫布 輸入 輸出 除錯記錄 語法樹    │
│ （程式碼頁的左側三標籤）           │ 播放列＋畫布                    │
└───────────────┴──────────────────────────────────────────────────────┘
```

- 展開後蓋住整個視窗，投影片的左側欄與舞台都在下面。
- 「← 返回投影片」放左上角，深底白字、比其他按鈕大；Esc 也能返回（焦點在程式碼編輯器內時除外）。
- 拿掉右上「儲存」：返回時自動存回投影片（第 6 節）。標題列右側只顯示狀態。
- 編輯狀態下的動畫頁：
  - 不顯示網站頂部列（`#top-bar`）、我的程式碼、範例側欄與手繪工具列；
  - 顯示左側三標籤與右側「畫布／輸入／輸出／除錯記錄／語法樹」分頁；
  - 頁內 RUN 保留。
- 返回後畫布已經是最新狀態（同一個畫布），左側輸入框顯示最新輸入。

### 5.3 技術作法：同一個 iframe
現在投影片用 `algorithm.html?asmEmbed=runtime`，編輯器另開 `algorithm.html?asmEmbed=editor`，是兩個 iframe。改為：
- **只保留投影片上的那個 runtime iframe**，刪除 `#algorithmEditorModal` 與第二個 iframe。
- **頁內模式可切換**：
  - 目前 `slides-embed.js`、`trace-editor.js`、`front.js` 都在載入時從網址讀一次 `asmEmbed` 就固定。
  - 改為由父頁送 `asm-embed-set-mode`（`runtime`／`editor`），iframe 切換 `body.asm-embed-runtime`／`asm-embed-editor`。
  - 進入編輯時接上左側設定標籤（`ASMTraceStudio.attach`）、調整 Ace 尺寸；回到 runtime 時寫回 `@asm-view` 並卸下。
  - 程式碼頁本身（沒有 `asmEmbed`）不受影響。
- **跳出投影片的縮放**：Reveal 用 CSS `transform` 縮放投影片舞台，在裡面的元素無法用 `position: fixed` 蓋滿整個視窗。
  - 進入編輯時，用 `Element.moveBefore()` 把 iframe 從投影片搬到頁面最外層的全螢幕容器；返回時再搬回原位。
  - `moveBefore` 搬移時 iframe 不會重新載入。已在 Chromium 152 以實際的 `algorithm.html?asmEmbed=runtime` 驗證：沒有 load 事件，頁內狀態保留。
- **過場（FLIP）**：
  1. 先把 iframe 放進全螢幕容器，以最終尺寸排版（左側編輯區＋右側畫布）。
  2. 用 `transform`（平移＋等比縮放）讓「右側畫布區」剛好對齊投影片上原本的畫布位置；用 `clip-path` 裁掉畫布區以外的部分（左側編輯區、右側分頁列），所以第一幀看起來和投影片上一模一樣。
  3. 動畫只改 `transform` 與 `clip-path`：畫布移到右側並放大，裁切範圍向左展開，左側編輯區看起來就是「一起靠過來」；標題列同時滑入。
  4. 過場中不改寬高，避免每幀重新排版與重新取景；結束後呼叫一次 `refreshViewportCamera`，把鏡頭對齊新的畫布大小。
  5. 投影片畫布與編輯畫布的長寬比不同時，以寬度等比縮放、上下裁切，內容不會被拉扁。
  6. 返回時反向播放，結束後把 iframe 搬回投影片並切回 runtime。
- **不支援 `moveBefore` 的瀏覽器**：退回「淡出淡入」並重新載入 iframe，再把目前幀、輸入與尚未存回的修改送回去；功能相同，只是沒有連續的過場。
- 開啟過一次後不再重新載入；第一次進入時，左側編輯區的 Ace 與設定標籤在 iframe 內延遲建立，標題列顯示「正在準備編輯器…」。

## 6. 同步與重新執行

### 同一份資料
因為投影片與編輯動畫是同一個 iframe，動畫、目前幀、程式輸出、除錯記錄本來就是同一份。需要處理的只有左側輸入框與投影片資料：
- 輸入：
  - 左側輸入框與 iframe 內的 `#inputArea`（編輯頁的「輸入」分頁）雙向同步；
  - 兩者都寫回投影片動畫資料的 `input`；
  - 在任一邊修改，另一邊立即顯示。
- 程式碼與 `@asm-view` 設定：只在編輯動畫頁修改；返回時寫回投影片資料。
- 執行結果：
  - 由 iframe 在每次執行後送出摘要（成功／失敗、輸出第一行），左側狀態文字顯示；
  - 完整輸出與除錯記錄就在同一個 iframe 的「輸出」「除錯記錄」分頁，不必另外保存或複製。

### 什麼時候執行、要不要重新編譯

| 情況 | 行為 |
|---|---|
| 左側只改輸入，按 RUN 或觸發自動執行 | 重新執行；程式碼沒變，伺服器直接重用快取的執行檔，不重新編譯 |
| 在編輯動畫頁改了程式碼並已 RUN，按「返回投影片」 | 動畫已是最新，直接存回，不重跑 |
| 在編輯動畫頁改了程式碼或輸入但沒 RUN，按「返回投影片」 | 存回後在背景重新編譯執行 |
| 只是打開再關閉、沒有修改 | 不執行 |
| 公開範例（本機副本） | 照現行規則只更新本機副本，不回寫官方教材 |

- 是否需要執行，以現有新鮮度指紋（紅點）判斷：程式碼、輸入或生成設定和目前動畫不一致時才執行。
- 執行中：
  - 畫布保留舊動畫並顯示「更新動畫中…」；
  - 可以繼續編輯其他投影片；
  - 同一張投影片再次修改時，取消尚未完成的那次，以最新內容重新執行。
- 成功：換成新動畫並停在第 0 幀，紅點熄滅，左側狀態顯示「已是最新」與輸出摘要。
- 失敗：
  - 保留原動畫與紅點，畫布上方顯示錯誤摘要與「開啟編輯動畫」；
  - 不把失敗結果蓋掉舊動畫，也不把未成功的更新標成已儲存（[Trace 快取與階段更新](../../../guides/trace-cache-updates.md)）；
  - 輸入與程式的修改照常保存。
- 放映模式不會觸發執行；放映看到的一律是最後一次成功的動畫。

## 7. 實作步驟（每步各自可驗證）
1. **runtime 只顯示畫布**：隱藏分頁列與四個分頁內容，拿掉播放列的 RUN；確認展示、編輯、放映三種狀態與鏡頭重新取景。
2. **左側欄動畫區塊**：
   - 編輯動畫按鈕、輸入框、RUN、狀態文字、自動執行（依 Q1）；取消舊執行；
   - 輸入框與 iframe `#inputArea` 雙向同步；
   - 確認只改輸入時伺服器回應執行檔快取命中（`X-Compile-Executable-Cache: HIT`）。
3. **頁內模式切換**：`asm-embed-set-mode` 訊息；`slides-embed.js`、`trace-editor.js`、`front.js` 的模式改為可變；編輯狀態的版面（隱藏網站頂部列、手繪工具列）。先不做過場，直接切換也要能正常編輯與返回。
4. **全螢幕容器與 `moveBefore`**：進入時搬到最外層、返回時搬回；不支援時退回重新載入並還原狀態。
5. **過場**：FLIP（`transform`＋`clip-path`）、標題列滑入、Esc、減少動態效果、結束後重新取景。
6. **刪除舊編輯器**：`#algorithmEditorModal`、第二個 iframe、`saveAlgorithmEditor` 與相關訊息。
7. **手機版**：左側欄在手機上是底部工具；動畫區塊改為底部面板中的一段；編輯頁直接切換不播放過場。
8. **文件與測試**（見第 9 節）。

## 9. 測試
- runtime：展示與編輯模式都沒有 `#subTabs` 與 RUN；畫布高度等於 iframe 高度扣掉播放列。
- 左側欄：
  - 只有動畫投影片顯示動畫區塊；展示模式沒有左側欄；
  - 改輸入後紅點亮起；按 RUN 或自動執行後紅點熄滅、狀態顯示輸出摘要；
  - 只改輸入時伺服器回應快取命中（未重新編譯）；
  - 執行中再修改會取消舊的那次。
- 同步：
  - 左側改輸入後開啟編輯動畫，「輸入」分頁是新的輸入；
  - 編輯頁改輸入或程式並返回，左側框與畫布都是新的；
  - 任一邊執行後，另一邊看到同一份輸出。
- 同一個畫布：
  - 進入與返回編輯動畫都不觸發 iframe 的 load 事件，頁內狀態（目前幀、播放狀態）保留；
  - 過場第一幀與投影片上的畫布位置一致（截圖比對容許 2px 誤差）；
  - 過場中 iframe 的寬高不變，只有 `transform`／`clip-path` 改變；
  - 減少動態效果時直接切換；
  - 模擬不支援 `moveBefore`：重新載入後目前幀與輸入正確還原。
- 完整編輯頁：
  - 返回按鈕可見並能回到原投影片；
  - 已 RUN 過時返回不重跑；改過但沒 RUN 時返回會重新執行；
  - 編輯狀態沒有網站頂部列與手繪工具列；回到投影片後沒有左側編輯區與分頁列。
- 失敗：保留舊動畫、錯誤列、修改仍保存；公開範例只更新本機副本。
- 回歸：`slide-canvas-toolbar`（目前因 `67bf65a` 失效，需先由該改動的負責代理修好；RUN 移到左側後此測試要改寫）、`presentation-mode-selection`、`slide-animation-parity`。

## 10. 風險
- **iframe 高度改變**：拿掉分頁列後，iframe 內畫布高度變大，已存的鏡頭與放映縮放要確認不跳動。
- **自動執行的成本**：以指紋判斷「真的變了才執行」，並取消過期的執行；連續修改多張投影片時，同時最多執行一張，其餘排隊。
- **執行檔快取被清除**：只改輸入時通常不編譯；快取被清掉時會退回完整編譯，時間較長，狀態文字照樣顯示「更新中…」。
- **與 `67bf65a`（執行配方）同時改動**：該提交改了投影片動畫的載入方式；實作前先確認 `runSlideAnimation` 與 runtime 訊息介面在最新統合分支上的樣子。
- **模式在載入後可切換**：`asmEmbed` 目前在三個檔案中於載入時固定，改為可變後，要逐一確認 runtime 專屬行為（隱藏可見性、放映鏡頭、草稿不寫入程式碼頁）在切換來回後都正確。
- **`moveBefore` 的瀏覽器支援**：Chromium 系列支援（已實測）；其他瀏覽器走「重新載入並還原」的退回路徑，需要單獨測試。
- **iframe 在投影片換頁時被卸載**：編輯中禁止換頁（編輯頁蓋住投影片）；返回時若原投影片已被刪除或移動，iframe 改放回目前投影片位置或直接卸載。
- **兩個代理共用**：會改動 `slides.js` 的編輯器與 RUN 區段，以及 `slides-embed.*`；實作期間避免其他代理同時修改這些區段。
