## 任務資訊
- 負責代理：Claude（Claude Code 桌面版）
- 分支：`claude/2026-11-16-slide-animation-editing`（從 intergration `75445de` 開出）
- 狀態：規劃，尚未實作；待使用者確認第 7 節。
- 依據：使用者 2026-11-16 指示：
  - 調整整個投影片的動畫編輯介面，先處理畫布上面的輸入、輸出、RUN 介面；
  - 除錯記錄和語法樹只在編輯模式呈現；
  - 點開輸入、輸出目前是硬生生佔據下半部，要有比較好的作法；

  - 編輯模式時「編輯動畫」顯示在左邊按鈕，並從浮動視窗改成完整頁面，要有明顯的返回按鈕。
- 取代：介面改版規劃階段 4 的「展開式編輯器」（示意圖 https://claude.ai/artifact/3V4741nMm3dQa1b8qBvYc7）。改為完整頁面後，不再需要畫布放大的 FLIP 過場。

## 1. 現況（以 2026-11-16 實際截圖為準）

| 狀態 | 現在的樣子 | 問題 |
|---|---|---|
| 展示模式（view／放映） | 動畫投影片上方有「畫布／輸入／輸出／除錯記錄／語法樹」分頁，下面是播放列與畫布 | 放映時不該出現這些分頁；分頁也佔掉投影片高度 |
| 編輯模式 | 同一排分頁；播放列多了 RUN | 分頁擠在投影片裡，字很小 |
| 編輯模式按「輸入」 | `#tab-input` 直接佔掉投影片下半部，畫布被壓到上半 | 畫布變形、看不到原本的構圖 |
| 編輯演算法動畫 | 左側欄最下方有「編輯演算法動畫」按鈕；按下後開浮動視窗（`#algorithmEditorModal`），裡面是 `algorithm.html?asmEmbed=editor`，連程式碼頁頂部列（演算法範例集、我的程式碼、畫布設定、編輯器、GitHub）都在 | 視窗沒有明顯的返回；右上只有「儲存」；內嵌頁的頂部列與投影片無關 |

相關程式：
- runtime iframe：`algorithm.html?asmEmbed=runtime`；分頁樣式在 `slides-embed.css` 的 `body.asm-embed-runtime #subTabs`。
- 編輯器：`slides.html` 的 `#algorithmEditorModal`；`slides.js` 的 `openAlgorithmEditor`／`closeAlgorithmEditor`／`saveAlgorithmEditor`。
- 左側欄按鈕：`#algorithmEditSlideBtn`（只在動畫投影片顯示）。

## 2. 目標
1. **投影片上的動畫只有畫布**：展示與編輯模式都不再有分頁列；播放列照舊（編輯模式多一個 RUN，見決定 Q1）。
2. **輸入、輸出、除錯記錄、語法樹移到左側編輯欄**：選到動畫投影片時才出現；除錯記錄與語法樹本來就只在編輯模式。
3. **打開時不擠壓畫布**：內容以側邊抽屜顯示，蓋在投影片舞台左側，畫布維持原本大小與構圖。
4. **編輯動畫改成完整頁面**：蓋住整個視窗，左上角有明顯的「← 返回投影片」。

## 3. 投影片上的動畫（runtime）
- `slides-embed.css`：`body.asm-embed-runtime #subTabs` 改為 `display: none`。`#tab-input`、`#tab-output`、`#tab-debug`、`#tab-syntax-tree` 在 runtime 一律不顯示，`#tab-canvas` 固定顯示。
- 展示模式：只剩播放列與畫布（與目前展示工具列相同，不含 RUN）。
- 編輯模式：播放列與畫布；RUN 是否留在播放列見 Q1。
- 畫布高度多出原本分頁列的 42px，鏡頭在 iframe 尺寸改變後照常重新取景（沿用 `refreshViewportCamera`）。

## 4. 左側編輯欄
選到動畫投影片時，左側欄最下方顯示一組「動畫」按鈕（取代目前單一的「編輯演算法動畫」）：

```
┌ 左側編輯欄 ──────┐
│ T  text          │
│ Σ  LaTeX         │
│ …（原有工具）     │
│ ── 動畫 ──────── │
│ {;} 編輯動畫      │  ← 開完整頁面（第 5 節）
│ ⌨  輸入          │  ← 開抽屜
│ ▤  輸出          │
│ 🐞 除錯記錄       │
│ 🌳 語法樹         │
└──────────────────┘
```

- 「編輯動畫」排第一、樣式最醒目（沿用目前的橘色強調）；其餘四個是一般工具按鈕，開啟時呈按下狀態。
- 只有編輯模式有左側欄，因此除錯記錄與語法樹自然只在編輯模式出現。
- 輸出有新內容、或除錯記錄有編譯警告時，按鈕上顯示小圓點提示（不自動打開）。

### 抽屜（取代「佔據下半部」）
- 按下輸入／輸出／除錯記錄／語法樹任一個，從左側欄右緣滑出一個抽屜：
  - 寬約 420px（可拖曳調整，記住寬度）、高度同舞台；
  - 蓋在投影片舞台上方，畫布本身不縮放、不移動。
- 同時只開一個抽屜：再按同一個按鈕、按抽屜右上 ×、或按 Esc 會關閉；按另一個按鈕則切換內容。
- 換到別張投影片：如果新投影片也是動畫投影片，抽屜保留並顯示新投影片的內容；否則關閉。
- 各抽屜內容：
  - **輸入**：等寬字的文字區。修改後投影片標記為「動畫需要更新」（紅點），抽屜底部有「套用並 RUN」；不按也會保存輸入，下次 RUN 時使用。
  - **輸出**：唯讀，最近一次 RUN 的程式輸出；RUN 失敗時顯示錯誤訊息。
  - **除錯記錄**：唯讀，編譯警告與除錯訊息。動畫播放記錄的「開始記錄／下載 JSON」等工具只留在完整編輯頁。
  - **語法樹**：唯讀檢視，可縮放平移。
- 資料流：
  - 內容來自 runtime iframe：iframe 在載入與每次 RUN 後送出 `asm-runtime-panels`（輸入、輸出、除錯文字、語法樹 SVG）。
  - 輸入修改由父頁寫回投影片資料，再送 `asm-runtime-set-input` 給 iframe。
  - 不在父頁重新執行任何程式。
- 為什麼不用其他作法：
  - 直接放在左側欄裡（展開成一段）：左側欄只有約 160px，輸出與語法樹放不下；
  - 浮在畫布上的小視窗：會擋住畫布中央，也要另外處理拖曳與位置記憶；
  - 抽屜貼著左側欄，關掉就恢復原樣，最接近「按左邊按鈕、在左邊看」。

## 5. 編輯動畫：完整頁面
- 取代 `#algorithmEditorModal` 的浮動視窗：改成覆蓋整個視窗的頁面（`position: fixed; inset: 0`），投影片的左側欄、舞台都被蓋住。
- 頁面頂端是投影片自己的標題列，取代內嵌頁的網站頂部列：

```
┌──────────────────────────────────────────────────────────────────────┐
│ [← 返回投影片]  第 10 張：Quick Sort 分區動畫     ● 已儲存    [儲存]   │
├───────────────┬──────────────────────────────────────────────────────┤
│ 原始碼 程式碼框 事件動畫   C++ ▶RUN │ 畫布 輸入 輸出 除錯記錄 語法樹    │
│ （程式碼頁的左側三標籤）           │ 播放列＋畫布                    │
└───────────────┴──────────────────────────────────────────────────────┘
```

- 「← 返回投影片」放左上角，深底白字、比其他按鈕大；Esc 也能返回（焦點在程式碼編輯器內時除外）。
- 內嵌的 `algorithm.html?asmEmbed=editor` 隱藏網站頂部列（`#top-bar`）、我的程式碼、範例側欄與手繪工具列，只保留左側三標籤與右側畫布分頁。完整頁面裡右側照舊有「輸入／輸出／除錯記錄／語法樹」分頁，因為這裡空間足夠。
- 儲存：決定見 Q2。目前的行為是「動畫已更新，尚未套回投影片，請按儲存」。
- 返回後回到原本那張投影片的編輯模式，畫布重新載入最新動畫；左側抽屜維持原本的開關狀態。
- 開啟時沿用現有 iframe（第二次開不重新載入）；載入中在標題列顯示「正在載入動畫…」。

## 6. 實作步驟（每步各自可驗證）
1. **runtime 只顯示畫布**：隱藏分頁列與四個分頁內容；確認展示、編輯、放映三種狀態與鏡頭重新取景。
2. **左側欄動畫按鈕組**：把「編輯演算法動畫」換成按鈕組（先只有「編輯動畫」可用）。
3. **抽屜與資料通道**：建立抽屜元件，以及 `asm-runtime-panels`／`asm-runtime-set-input` 兩個訊息；依序接上輸出、除錯記錄、語法樹（唯讀），最後是輸入（可寫並標記需要更新）。
4. **完整編輯頁**：標題列與返回按鈕、隱藏內嵌頁的網站頂部列、Esc、儲存流程（依 Q2）。
5. **手機版**：左側欄在手機上是底部工具；抽屜改為從底部升起的面板，高度約 60%。
6. **文件與測試**（見第 8 節）。

## 8. 測試
- runtime：展示與編輯模式都沒有 `#subTabs`；畫布高度等於 iframe 高度扣掉播放列。
- 左側欄：只有動畫投影片顯示按鈕組；展示模式沒有左側欄。
- 抽屜：
  - 開、關、切換、Esc；換到非動畫投影片時關閉；
  - 畫布的位置與大小在開抽屜前後不變；
  - 輸入修改後紅點亮起，「套用並 RUN」後熄滅、輸出抽屜更新。
- 完整編輯頁：
  - 返回按鈕可見並能回到原投影片；
  - 依 Q2 驗證自動套用與編譯失敗的詢問；
  - 內嵌頁沒有網站頂部列。
- 回歸：`slide-canvas-toolbar`（目前因 `67bf65a` 失效，需先由該改動的負責代理修好）、`presentation-mode-selection`、`slide-animation-parity`。

## 9. 風險
- **iframe 高度改變**：拿掉分頁列後，iframe 內畫布高度變大，已存的鏡頭與放映縮放要確認不跳動。
- **輸入的保存規則**：目前輸入存在投影片的動畫資料中，並與 freshness 指紋相關。抽屜修改輸入的時機與紅點規則要與 [Trace 快取與階段更新](../../../guides/trace-cache-updates.md) 一致。
- **與 `67bf65a`（執行配方）同時改動**：該提交改了投影片動畫的載入方式；實作前先確認 runtime 的訊息介面與最新統合分支一致。
- **兩個代理共用**：會改動 `slides.js` 的編輯器區段與 `slides-embed.*`；實作期間避免其他代理同時修改這些區段。
