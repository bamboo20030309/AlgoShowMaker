# 已可見欄位的清零退場

使用者指出線段樹64→65幀的lazy原本可見，應保留lazy=0事件，清零後才退場。前次以after被hide隱藏一律停用動畫，範圍過大。

## 行為

- 已隱藏且仍隱藏的欄位：維持即時更新，不產生動畫。
- 原本可見、清成被hide隱藏的0：啟用賦值，舊+3保留至0抵達，提交資料0；呈現用文字暫留0，沿用500ms停留與100ms淡出，結束移除欄位和逗號。
- 60→61的sets接替lazy：保留原位替換，不另播清零，避免已被=5覆蓋後又播放多餘的0。
- 非零隱藏哨兵值維持原先即時處理，本輪不改成顯示巨大哨兵數字。

新增共用fieldCellKey／fieldReplacementReset，依同格與鄰近實際寫入辨識交接，沒有用幀末結果猜測。資料提交仍由重播計畫負責；暫留0只在效果的afterReplay階段顯示，不修改Trace或hide條件。欄位opacity由當前效果提供，避免目的幀的隱藏狀態先讓舊lazy消失。

## 驗證

multi-field-replay新增新編譯與既有Trace的64→65幀、1倍／4倍速：lazy=0 checkpoint為animated，有0的下落副本；提交前+3保持可見，提交後0持續呈現既有停留階段，最終只剩30且沒有逗號。保留60→61原位覆蓋、24→25賦值、其他欄位更新與隱藏、格式、自訂設定及儲存重開檢查。
