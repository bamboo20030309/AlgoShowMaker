# 範例預建 Trace 與多人後端快取

## 任務目標

- 官方範例投影片不在每次開啟時重新分析、編譯及執行固定程式碼。
- 程式碼相同但輸入改變時重用 C++ 執行檔；程式碼、編譯器或引擎版本改變時自動失效。
- 相同程式碼、輸入與 trace 設定可重用伺服器 Trace，並限制磁碟容量與保存時間。
- 保留同步 `/compile` 相容性，另提供適合多人尖峰的非同步提交、狀態查詢與結果下載 API。
- 單核心、1 GB、128 PIDs 的 Docker 上限維持不變；以公平排程、工作隔離、快取與背壓降低尖峰成本。

## 驗收條件

- 官方 guest decks 內嵌可驗證來源、輸入與引擎版本的預建 Trace。
- 舊 asmdeck 或失效的預建 Trace 仍走既有重建流程，不會載入錯誤動畫。
- Trace 快取包含輸入與 trace 設定；執行檔快取不包含輸入，但包含來源、編譯器、flags 與引擎版本。
- 非同步工作只能由原擁有者查詢或下載，結果與除錯訊息不跨使用者混用。
- 50 個不同瀏覽器身分可在隔離服務完成一次尖峰測試，工作結束後佇列清空。

## 不在本次範圍

- 不提高 Docker CPU、記憶體或 PID 上限。
- 不合併 main、不發布 release、不部署遠端正式機。
- 不執行全部演算法動畫回歸；只驗證本次涉及的範例載入、快取、佇列與執行保護。
