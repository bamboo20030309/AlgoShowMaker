# 連續宣告與指標初始化的播放修正

## 問題與原因

合併排序第 26 幀的 `int i = L, j = mid + 1;`，Trace 原本已按宣告 i、賦值 i、宣告 j、賦值 j 記錄。播放端卻把指標初始化歸成零時間的位置更新，略過兩個賦值步驟；程式反白也共用包含型別與初始化算式的範圍。

## 行為規則

- 宣告只反白共用型別與當前變數名稱；賦值只反白該變數的初始化算式，不帶前方型別。
- 指標初始化與 for 標頭初始化都是正常賦值步驟。指標初始位置直接對應正確格子，不額外從第 0 格移入；仍播放數值賦值。
- 宣告 220ms、指標賦值 1760ms，各自套用事件間隔。500ms 與明確 0ms 都依原設定；倍速只縮短實際經過時間。
- 普通程式反白 400ms、return 260ms、既有比較及其他賦值節奏不變。明確停用的賦值仍維持停用。

## 相容性與實作

在共用 code model 使用已保存的 AST 型別／declarator 範圍及事件名稱，投影畫面反白，不修改 Trace 原始碼位置或持久化資料。既有公開投影片可直接載入，無新增必填欄位，也不需重編譯 Trace。Studio 指令選取保留完整原始範圍與獨立宣告／賦值選項。

- `declaration-highlight.test.js`：新產生的連續宣告、無初始化宣告與舊 AST 範圍投影，確認不改寫原始資料。
- `merge-declaration.browser.test.js`：實際載入既有公開合併排序並播放第 25→26 幀。以獨立標準答案核對四次反白、220/1760ms 時間與每段間隔，涵蓋 0/500ms、1/2 倍速及明確停用賦值。另檢查賦值期間實際 SVG 指標不額外位移。
