# 事件與動畫固定規格

更新：2026-11-04。依使用者確認恢復舊版作用時間，保留新版事件順序與狀態提交。本文件描述目標規格；是否已由目前程式通過，必須另外查看驗證報告。列出案例不代表測過，更不代表全部通過。

## 單一事件流程

程式在後端執行一次，Trace 保存實際事件、來源、目標、前後值、執行順序與選中的分支。播放不重新執行 C++，也不從相同數值猜來源。前端依顯示綁定產生動作計畫，再由排程器統一管理開始、完成、提交與清理。

基本視覺動作有六類：入場／退場、複製、搬移、強調、顯示提示、鏡頭移動。物件建立、定位、排版、狀態提交、快照保存與清理屬於內部操作。內部操作不能偷偷提前換值。

每個計畫遵循「準備 → 播放 → 提交 → 收尾」。同一事件中沒有相依的動作可以同步；不同事件預設依實際執行順序。資料、程式行與運算的身分不依演算法名稱、變數名稱或教材幀號判定。

## 一倍速共用時間

| 動作 | 毫秒 | 先後或同步 |
| --- | ---: | --- |
| 入場／退場 | 220 | 同一批新增或移除可同步 |
| 賦值數字／格子搬移 | 500 | 準備 160 ms 後開始，多來源同步，660 ms 抵達提交 |
| 賦值完成停留／收尾 | 500／100 | 一般賦值總計 1260 ms；停留期間不再次提交 |
| 指標移動 | 520 | 同一變數的多個綁定同步；指標賦值前另有 500 ms 來源停留 |
| 交換 | 520 | 兩格同步，抵達後提交 |
| 比較進場／觀察 | 180／400 | 恢復原版進場；二元比較先觀察，單值條件框隨進場顯示 |
| 比較動作 | 300 | 大小比較兩格共同上抬後縮放；相等比較前 150 ms 對齊、後 150 ms 靠近 |
| 比較結果 | 420 | 二元結果第 580 ms 起隨動作淡入，第 880 ms 完全顯示 |
| 比較復位 | 260 | 結果後復位；整個比較 1560 ms |
| 無搬移的單純強調 | 400 | 不改變正式位置；不能拿來取代同值賦值 |
| 鏡頭調整 | 520 | 先到位，再播放主要事件；保留自訂與明確 0 ms |
| 自動 highlight、提交、建立複本、清理 | 不額外占時 | 附著於所屬操作 |

實際時間為基本時間除以播放倍率。修改倍率在下一事件生效。同一組同步搬移共用時間，不因距離各自提早提交。事件之間沒有額外自動等待；明確的使用者控制值仍需尊重。

## 宣告與賦值

| 案例 | 原始操作 | 固定答案與動作 |
| --- | --- | --- |
| E01 | `int uninitialized;` | 空格入場；不捏造初值、不產生賦值 |
| E02 | `int initialized = b;` | b=3；宣告空格 220 ms，再獨立賦值 1260 ms；第 880 ms 提交值 |
| E02_CONTAINER | `vector<int> copied = arr;` | [4,7]；空容器入場 220 ms，再兩格同步複製，抵達提交時間同 E02 |
| E03 | `a = b;` | a：1→3；b 整格複製飛入，b 保留 |
| E04 | `arr[1] = arr[0];` | arr：[4,7]→[4,4]；來源整格保留，僅目標值改變 |
| E05 | `a = b + c;` | 3+8=11；兩數字同步直接飛入，第 660 ms 抵達前 a=3，抵達後 a=11 |
| E06 | `a += b;` | 11+3=14；a 舊值不搬移，b 數字飛入 |
| E07 | `a = 8;` | a：14→8；8 從目標上方落入 |
| E08 | `a = b + b;` | 3+3=6；兩份數字，b 的讀取 highlight 只有一份 |
| E09 | `a = a;` | a=6 不變；仍按一般整格複製賦值播放 1260 ms，不以值相同略過動畫 |
| E10 | 容器 `a = b;` | [1,2]→[3,8,5]；調整格數，各格同步複製，名稱與外框不搬移 |
| E11 | `ans = solve(source);` | source=7、return=8、ans：0→8；從可見回傳位置飛入，否則從目標上方落入 |
| E12 | b 不可見，`a = b;` | a：1→3；數字從 a 上方落入，不臨時建立 b 格子 |
| E13 | b 可見、c 隱藏，`a = b+c;` | b=3 從原位、c=8 從目標上方，全部抵達後 a=11 |
| E14 | c 不可見，`c = b;` | c：8→3；更新資料與程式提示，不生成目標或飛行複本 |

複製格子的飛行外觀來自來源；落地保留目標原本的顏色、尺寸與樣式。運算賦值只搬數字，不額外建立運算式區域。

## 比較與選值

| 案例 | 原始操作 | 固定答案與動作 |
| --- | --- | --- |
| E15 | `b < c` | 3<8 為 true；兩格共同上抬 15px，右大放大、左小縮小，最後復位 |
| E16 | `b != c` | 3≠8 為 true；先對齊再靠近，不相等時左／右分別錯開 -5／+5px |
| E16_EQUAL | `b == b` | 3=3 為 true；原版同格比較用兩份暫時呈現，共同上抬 15px，結束恢復原物件 |
| E17 | `a = min(b,c);` | 選 b=3；先比較 1560 ms，再一般賦值 1260 ms；第 2220 ms 抵達提交 |
| E17_MAX | `a = max(b,c);` | 選 c=8；相同選值流程，最後 a=8 |
| E17_TIE | `a = min(b,b);` | 相等時選第一個來源；不得以來源去重弄丟選值順序 |
| E18 | `a = result ? b : c;` | result=true，選 b=3；不執行、不 highlight c |
| E19 | `a = min(b,c)+d;` | 先選 3，再與 d=2 同步飛入，a 最後一次更新為 5 |
| E20 | `false && (++d > 0)` | 結果 false，d 保持 2；不得播放 ++d 或右側比較 |
| E20_OR | `true || (++d > 0)` | 結果 true，d 保持 2；同樣不得求值或播放右側 |

依 2026-11-04 最新指示，使用目前排程恢復 504d51c 的原始比較視覺。符號保留程式運算子，條件不成立時在符號上加斜線，不另附 true／false，也不按數值反轉比較方向。例如 `8 < 3` 保留 < 並加斜線；`3 != 3` 保留 ≠ 並加斜線。相等比較恢復對齊、靠近與不等時少量上下錯開；大小比較的指標仍跟隨格子，標籤不縮放。事件身分、正式值提交、讀取設定、間隔、倍速及暫停續播仍沿用目前實作。

## 交換與容器

| 案例 | 操作 | 固定答案與動作 |
| --- | --- | --- |
| E21 | 不同格交換 | [3,8,5]→[8,3,5]；520 ms 同步交換 |
| E22 | 不同格的相同值交換 | [8,8]→[8,8]；仍有兩格交換動畫 |
| E23 | 同格與自己交換 | [8,3,5] 不變；400 ms 強調，不位移 |
| E24 | 在索引 1 插入 9 | [8,3,5]→[8,9,3,5]；外框擴大與騰位同步 300，再固定外框、入場 220 ms |
| E25 | 刪除索引 1 | [8,9,3,5]→[8,3,5]；固定外框、先退場 220，再補位與縮框同步 300 ms |
| E26 | `resize(5,6)` | [8,3,5]→[8,3,5,6,6]；新格同步入場 220 ms |
| E27 | `clear()` | 元素一起退場 220 ms；保留空容器與名稱 |
| E28 | `assign(3,7)` | []→[7,7,7]；一個語意賦值事件，不加入內部建構呼叫 |
| E29 | `a = move(b)` | a=[3,8,5]；轉移後 b 依執行結果，不能把「一定為空」寫成答案 |

重疊只核對穩定定點。交換途中合法交叉不算失敗，不得改路徑來躲避驗證。

## 函式、流程與讀取

| 案例 | 情境 | 固定答案與動作 |
| --- | --- | --- |
| E30 | 呼叫 solve | 實參 7；程式碼提示與呼叫狀態，參數遵循複製／轉移規則 |
| E31 | 進入 solve | value=7，local=8；各次呼叫有獨立 activation 與 lifetime |
| E32 | 離開函式 | 清理本次呼叫；自然結束不提早毀掉最後教學畫面 |
| E33 | return local | 回傳 8；呈現回傳，再離開並接續賦值 |
| E34_CONTINUE | i=1 時 continue | total=0，該輪後續 total+=i 不執行 |
| E34_BREAK | i=3 時 break | total=2；跳出迴圈，不再執行後續累加 |
| E35 | cout | 完整輸出為 `8 2\n`；只強調實際輸出的資料 |
| E36 | b+c 的讀取 | b、c 持續 highlight、不閃爍；附著 E05，額外時間為 0 |

讀取 highlight 在所屬操作開始時出現、完成後解除，和手寫 highlight 分層。重複讀取不反覆觸發；未執行分支、索引運算的輔助變數不順便擴大強調範圍。

## 指標

| 案例 | 情境 | 固定答案與動作 |
| --- | --- | --- |
| P01 | 宣告 j=1 | 直接在索引 1 入場 220 ms |
| P02 | i++ | i：0→1，移動 520 ms |
| P03 | j=i-1 | j：1→0；指標賦值 1760 ms，再移動 520 ms；第 1160 ms 提交值 |
| P04 | j=p[2] | p[2]=1，j：0→1；來源數字飛入 500 ms，其他階段同 P03 |
| P05 | j=0 | 0 從數值框上方落入，再移至索引 0 |
| P06 | j 同時綁 s、p | j：0→2；數值更新一次，兩個指標同步 |
| P07 | i++ 與 i-1 | i：1→2；衍生指標 0→1，不新增賦值事件 |
| P08 | j=-1 | 左側邊界外仍可見 |
| P08_RIGHT | j=3、長度 3 | 右側邊界外仍可見 |
| P09 | i<j | i=2、j=3，結果 true；比較後回各自索引位置 |
| P10 | 明確退場 j | 淡出 220 ms；不改變資料值 |

指標身分包含綁定目標與生命週期。s 上的 j 和 p 上的 j 不是同一個畫面物件，不能因名稱相同就從另一個物件飛來。正式位置、排列偏移與暫時動畫偏移分開管理。

## 固定答案與驗證入口

完整機讀答案位於 `algo-vis-backend/tests/fixtures/event-contracts/manifest.json`，含 7 份 C++ 與 67 條規格。每份 C++ 使用 `// CASE <ID>` 指向來源行；不綁定可被教材改動的頁碼或幀號。函式進出、read、控制情境可能需觀察整個 activation 或外部操作，不能只找同一行的一個事件。

判定 helper 為 `tests/helpers/event-contract-oracle.js`，只載入手寫答案與嚴格比較已觀察欄位，不依賴 renderer 或計畫來產生答案。缺少必要欄位必須失敗，重複來源陣列不得去重。實際命令與報告解讀見[驗證手冊](../guides/event-validation.md)。

## 序列外框階段（2026-11-04）

normal 中間插入及 push_back：0～300 ms 擴框（中間插入同時挪位），300～520 ms 新格子與 index 入場，外框保持最終大小。erase 及 pop_back：0～220 ms 格子與 index 退場，外框保持原尺寸；220～520 ms 補位與縮框同步。尾端操作省略不需要的格子挪位，但保留同一階段順序。resize、clear、整體 assign 保留各自規則。

固定時鐘驗證入口為 algo-vis-backend/tests/sequence-outerframe-phases.browser.test.js，對四種操作在 1／2 倍速採樣實際外框 SVG 尺寸，核對 0、110、219、220、299、300、410、520 ms。列寬計算保留原本換列政策，不能把縮小後格數誤當為舊陣列的換列上限。

## 新格子與數字同步入場（2026-11-04）

insert／push_back 的入場階段須同時呈現格子與數字。可見來源使用原有整格複本；常數與隱藏來源在目的位置顯示帶數字的暫時格子，兩者一起淡入。正式 replay 值及 presence 仍等事件完成才提交，提交時接手正式格子、移除暫時呈現，不把數字延遲到提交瞬間才顯示。index 沿用同一入場進度。resize 新增格子也使用帶數字的入場呈現。

## 隱藏程式碼的畫面生命週期（2026-11-04）

@code hide 繼續抑制區段的執行事件。若同一生命週期、已可見序列的前後幀可確認只有尾端新增或刪除（保留的前綴資料相同），播放器產生暫時的 visual-insert／visual-remove 排程，沿用先擴框再入場、先退場再縮框的規則。這不是推定原本呼叫 push_back／pop_back，不產生可儲存的假執行事件。已有操作事件（包含明確關閉的事件）及不同遞迴生命週期不使用此補排程。無法由已儲存資料確定的中間變化不猜造來源或操作。

## render 的生命週期分工（2026-11-04）

無 runtime 事件的尾端增減補排程目前只作用於 render normal。disk 的圓盤由連續身分追蹤跨柱位置，不能套用一般陣列的新格入場／退場遮罩；heap 等其他 renderer 也保留既有幾何規則。暫時視覺補排程在 frame handoff 的前段執行，不排在後續 output／call 提示之後；原本真實事件之間的執行順序不改變。鏡頭、結構或新節點入場所需的既有 barrier 仍保留。

## 讀取強調預設（2026-11-04）

讀取仍附著於所屬操作，不增加獨立停頓。顯示預設關閉；事件設定面板的「讀取強調」開啟後才建立 highlight，預設顏色為純紅色 red（#ff0000）。設定保存於 studio.eventSettings.readHighlightEnabled（布林值）與 readHighlightColor（預設 red）。缺少欄位的舊資料視為關閉；明確 true／false 與自訂色保留，設定可隨 @asm-view、投影片、Trace 引用與帳號偏好保存。不恢復已移除的逐步讀取事件開關。
