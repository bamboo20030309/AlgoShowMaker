# 驗證集設計與執行時機

盤點日期：2026-10-06；範圍：intergration。本文區分現有實作與待新增項目，未執行全套測試，因此檔案數不代表通過數。

## 現有設計

目前 tests 頂層共有 241 個 .test.js：123 個 .browser.test.js、33 個 .integration.test.js、85 個其他測試檔。這是依檔名統計，其他測試也可能依賴編譯器或服務；373 是歷史執行案例數，不能當成現有案例數。

| 層級 | 用途 | 執行原則 |
|---|---|---|
| V0 | 文件、靜態文字、CSS、版面 | 差異與必要畫面確認 |
| V1 | 編輯器、物件、儲存等非動畫功能 | 最小相關測試；不跑演算法動畫集 |
| V2 | 指令、事件、Trace、動畫、camera、keep | 相關分類與小型 fixture；觀察實際受影響定點 |
| V3 | 跨模組與大型動畫回歸 | 主代理依風險選擇；子代理不得啟動 |

細項 A～M 分類及權限見根目錄「子代理驗證分級通知.md」。建議日常索引收斂為下列領域，沿用既有測試，不重新寫一份重複測試。

| 領域 | 現有代表與核實重點 |
|---|---|
| 指令／事件 | frame、preset、layout、迴圈展開、宣告／賦值及事件順序 |
| 動畫／幾何 | keep、指標、style、camera、箭頭、前後切幀與播放 |
| 編輯器／物件 | text、table、structure、code、LaTeX、混合選取、剪貼簿 |
| 資料相容／儲存 | 新物件、缺少欄位的舊物件、自訂值／明確關閉、儲存後重開 |
| 載入／效能 | scene-load-performance、sample-progressive-load、LOD、分塊與重用 |
| 後端／隔離 | compile-context、compile-job-queue、compile-job-registry、compile-cache、artifact-cache、HTTP 限制 |
| 範例／教材 | guest-gallery-hints、八皇后及 Merge Sort 專項、匯入與已存 Trace |
| 工具本身 | 回歸續跑、報告、測試伺服器及瀏覽器隔離 |

完整入口 npm run regression 執行靜態檢查、Node 測試，再執行瀏覽器動畫；另有 tests-only／animation-only 入口。臨時服務採隔離埠，報告放在 algo-vis-backend/test-results，不提交報告或編譯產物。

大型動畫目前有 13 個案例：arrow-identity、quick-style-swap、insertion-style-labels、defaults、style-frame-completion、recursive-roles、function-call、highlight-swap、bubble、insertion、selection、heap、quick-recursion。另有 cloud-storage-browser、slide-order-toggle、deck-import-repair 三個前置項目。部分案例只驗證有限幀，不等於所有演算法完整播放。

動畫使用 runtime iframe 一種環境，預設三個 worker 平行處理案例，前置項目先執行。一般演算法介面負責產生 Trace，嵌入／匯入另做契約確認，不重複在多個介面完整播放同一動畫。重疊只判斷事件／幀邊界，保留動畫中合理交叉。

compile-load-test 已有 cache、cold、mixed、isolation、limits 情境；一般情境預設 50 clients，limits 包含正常／TLE／OLE／MLE。壓測存在不代表目前每次整合都會執行，也不能據此宣稱所有硬體都支援 50 人。

## 大型驗證現在何時跑？

目前沒有追蹤中的 GitHub Actions 或其他 CI workflow。建立 PR 不會自動觸發大型驗證；它由主代理依整合範圍手動執行。v4.11 發布候選有專用增量入口，但不是通用 PR 門檻。

建議後續採用以下觸發規則；這是建議，尚未建立 CI：

| 時機／改動 | 驗證 |
|---|---|
| 文件／純版面／教材文字 | V0／V1；PR 也不啟動大型動畫 |
| 一般功能 PR／整合 | 靜態檢查與相關分類測試 |
| 指令解析、runtime、排程、共用 renderer 核心修改 | 主代理跑受影響大型案例；廣泛影響時跑完整矩陣 |
| 發布候選 | 核實本候選所需基準與增量證據；核心變動需要完整回歸，不因純文字發布重跑動畫 |
| 佇列、資源限制、部署規格變動或演示前 | 隔離環境執行 50-client 壓測及限制／隔離情境 |

## 優先新增／補強

1. **P0：通過紀錄有效性。** 現有續跑檢查清單，未綁定原始碼／測試／fixture 內容與環境版本。補入相關依賴指紋；變動影響到哪些已通過案例，就使那些案例失效。相同候選仍只重跑失敗／未完成項目，不能跨程式變更盲目沿用通過結果。修正前由主代理核對來源，失效範圍無法判斷時開新一輪。
2. **P1：正式範例契約。** 把目前人工核實的實際 catalog、檔案存在、名稱／標籤、原生匯入、縮圖、Trace 可讀與未改程式時不觸發編譯，做成固定小測試。包含 ID Trace 缺失／過期時的清楚錯誤或修復，不只測 mock 卡片。
3. **P1：大型矩陣補代表案例。** Merge Sort 遞迴／倍增與八皇后陣列／位元已有局部測試，但未列入上述大型矩陣。加入小輸入定點；BIT、Segment Tree、DP 按不同機制選代表。檢查 keep、遞迴生命週期、指標、最終結果與 JSON 往返，不全部演算法全部幀重播。
4. **P1：多人故障後恢復證據。** 延伸既有佇列／快取／限制測試，串起取消或斷線、超限、TLE／OLE／MLE 後下一個正常工作仍成功、子程序清除、各使用者訊息不混入與資源回落。已有單項不再重寫，補端到端組合與可量測斷言。
5. **P2：效能與編輯組合。** 在既有載入／LOD／物件測試上，加入首幀時間、長時間換程式／投影片後資源趨勢，以及混合 text＋structure＋code 的縮放、複製與重開組合；門檻需先取得固定環境基準，不憑空指定毫秒數。

## 索引與維護方式

建議新增共用測試 manifest：每個測試標註領域、V 級、服務／編譯器／瀏覽器需求、依賴、fixture 與成本。用同一份 manifest 產生分類與大型案例清單，避免 regression.js 和 animation-browser.js 各維護一份名單。這項尚未實作。

新增測試必須記錄要防止的回歸；不因函式存在就寫鏡像測試。結果須附版本、環境、執行範圍及失敗證據。環境不可用與未執行均須明列，不得標成通過。
