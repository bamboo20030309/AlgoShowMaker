# 驗證集設計與執行時機

盤點日期：2026-10-06；範圍：intergration。本輪已補強相關驗證；未執行全套測試，檔案數不代表通過數。

## 現有設計

目前 tests 頂層共有 256 個 .test.js：130 個 .browser.test.js、34 個 .integration.test.js、92 個其他測試檔。這是依檔名統計，其他測試也可能依賴編譯器或服務；373 是歷史執行案例數，不能當成現有案例數。首次完整 V3 的 247 檔為當時的歷史規模；新增測試也須纳入下一輪依賴驗收。

| 層級 | 用途 | 執行原則 |
|---|---|---|
| V0 | 文件、靜態文字、CSS、版面 | 差異與必要畫面確認 |
| V1 | 編輯器、物件、儲存等非動畫功能 | 最小相關測試；不跑演算法動畫集 |
| V2 | 指令、事件、Trace、動畫、camera、keep | 相關分類與小型 fixture；觀察實際受影響定點 |
| V3 | 跨模組與大型動畫回歸 | 主代理依風險選擇；子代理不得啟動 |

細項 A～M 分類及權限見根目錄「子代理驗證分級通知.md」。建議日常索引收斂為下列領域，沿用既有測試，不重新寫一份重複測試。

| 領域 | 現有代表與核實重點 |
|---|---|
| 指令／事件 | frame、preset、layout、迴圈展開、宣告／賦值及事件順序 |
| 動畫／幾何 | keep、指標、style、camera、箭頭、前後切幀與播放 |
| 編輯器／物件 | text、table、structure、code、LaTeX、混合選取、剪貼簿 |
| 資料相容／儲存 | 新物件、缺少欄位的舊物件、自訂值／明確關閉、儲存後重開 |
| 載入／效能 | scene-load-performance、sample-progressive-load、LOD、分塊與重用 |
| 後端／隔離 | compile-context、compile-job-queue、compile-job-registry、compile-cache、artifact-cache、HTTP 限制 |
| 範例／教材 | guest-gallery-hints、八皇后及 Merge Sort 專項、匯入與已存 Trace |
| 工具本身 | 回歸續跑、報告、測試伺服器及瀏覽器隔離 |

完整入口 npm run regression 執行靜態檢查、Node 測試，再執行瀏覽器動畫；另有 tests-only／animation-only 入口。臨時服務採隔離埠，報告放在 algo-vis-backend/test-results，不提交報告或編譯產物。

大型動畫共用矩陣目前有 20 個案例，原有 13 個為：arrow-identity、quick-style-swap、insertion-style-labels、defaults、style-frame-completion、recursive-roles、function-call、highlight-swap、bubble、insertion、selection、heap、quick-recursion。新增 merge-recursive、merge-bottom-up、queens-array、queens-bits、bit-query、segment-query、lcs-matrix 七個代表案例；使用小輸入核對完整程式結果，八皇后只錄製前 12／16 幀，避免大量棋盤快照使錄製資料膨脹。另有 cloud-storage-browser、slide-order-toggle、deck-import-repair 三個前置項目。部分案例只驗證有限幀，不等於所有演算法完整播放。

動畫使用 runtime iframe 一種環境，預設三個 worker 平行處理案例，前置項目先執行。一般演算法介面負責產生 Trace，嵌入／匯入另做契約確認，不重複在多個介面完整播放同一動畫。重疊只判斷事件／幀邊界，保留動畫中合理交叉。

compile-load-test 已有 cache、cold、mixed、isolation、limits 情境；一般情境預設 50 clients，limits 包含正常／TLE／OLE／MLE。壓測存在不代表目前每次整合都會執行，也不能據此宣稱所有硬體都支援 50 人。

## 大型驗證現在何時跑？

目前沒有追蹤中的 GitHub Actions 或其他 CI workflow。建立 PR 不會自動觸發大型驗證；它由主代理依整合範圍手動執行。v4.11 發布候選有專用增量入口，但不是通用 PR 門檻。

建議後續採用以下觸發規則；這是建議，尚未建立 CI：

| 時機／改動 | 驗證 |
|---|---|
| 文件／純版面／教材文字 | V0／V1；PR 也不啟動大型動畫 |
| 一般功能 PR／整合 | 靜態檢查與相關分類測試 |
| 指令解析、runtime、排程、共用 renderer 核心修改 | 主代理跑受影響大型案例；廣泛影響時跑完整矩陣 |
| 發布候選 | 核實本候選所需基準與增量證據；核心變動需要完整回歸，不因純文字發布重跑動畫 |
| 佇列、資源限制、部署規格變動或演示前 | 隔離環境執行 50-client 壓測及限制／隔離情境 |

## 本輪已補強

- **通過證據**：regression 與發布候選入口保存原始碼、測試、fixture、共用依賴和環境指紋。未提交的修改也會使相關通過紀錄失效；未變更項目續用，新增測試排入待跑。舊紀錄缺少指紋時不能直接沿用。瀏覽器／服務的動態依賴採保守範圍，可能使多個案例重跑。
- **正式範例**：guest-gallery-assets 檢查目前 15 份實際教材的封裝完整性、Trace ID 與程式／輸入指紋；guest-gallery-contract.browser 檢查實際卡片、名稱、標籤、縮圖，以及新 Merge Sort／八皇后的開啟不觸發編譯。缺失 ID Trace 的匯入須報錯。這不等於所有舊教材都已免重新編譯。
- **代表動畫**：上述七個案例加入共用矩陣。驗證器核對來源程式後才取 Trace，核對完整輸出或最終陣列，再於 runtime iframe 檢查動畫。LOD overview 按實際合併網格路徑判斷可見性；viewport culling 另核對節點仍存在、完整透明度、裁切標記和超出畫布 160px 的實際位置，不能掩蓋畫布內隱藏或刪除。
- **故障恢復**：compile-recovery.integration 涵蓋 CE／TLE／OLE／MLE、佇列滿載、取消、跨使用者讀取禁止、訊息隔離、正常工作恢復與資源回落。Windows 沒有 Linux 的記憶體限制機制，MLE 明確列為未適用；用隔離 Linux Docker 執行該項，不能將 Windows 略過視為通過。
- **效能／相容性**：scene-resource-lifecycle.browser 記錄首幀／完整載入時間、60 次程式切換後 DOM 與 GC 記憶體趨勢；時間和 heap 先建立基準，不使用未經量測的硬門檻。混合物件沿用 mixed-object-paste.browser，涵蓋 text＋structure＋code、縮放、樣式、undo／redo、儲存重開。預設線篩加入取消下載與旧 Trace 缺欄位／明確關閉設定／快取重開檢查。

## 索引與執行

Trace 歷史故障的畫面驗收另見 [固定行為規則](Trace固定行為規則.md)。固定索引／作者順序／比較方向／完成可見性的獨立契約由 `scripts/trace-behavior-rules.js` 判定；實際瀏覽器測試提供 SVG 樣本，`animation-assertions.js` 保留 keep、定點重疊與共用計畫提交時序檢查。兩種答案必須分開標示，避免計畫本身錯誤仍自證正確。

共用 scripts/validation-manifest.js 產生小測試領域、V 級、環境需求、依賴與成本索引，以及大型動畫清單。小測試分類為自動推估，代理仍須依實際資料流判斷，不可將索引當成啟動 V3 的授權。

在 algo-vis-backend 執行：

- npm run test:inventory：只列出索引，不執行測試。
- node --test tests/validation-evidence.test.js tests/regression-resume.test.js：驗證續跑與證據失效。
- node --test tests/guest-gallery-assets.test.js tests/guest-gallery-contract.browser.test.js：核對實際教材資產與畫面，瀏覽器測試自行使用隔離服務。
- npm run validate:backend-linux：隔離 Docker 容器執行故障恢復，預設使用現有 algo-vis-backend-backend image；需 Docker 與已建置映像。沒有公開埠，不掛載使用者資料庫。
- node --test tests/scene-resource-lifecycle.browser.test.js：建立資源趨勢基準，報告寫入忽略的 test-results。

大型矩陣仍只由主代理依影響範圍選案例；本次沒有加入 PR 自動 CI。預設線篩的完整與首幀資產已重建為引擎 13，116 幀；取消載入不產生未處理 Promise 錯誤。Trace bundle 只接受可相容的已知較舊格式與來源指紋，不接受未來版本或已改動程式。

新增測試必須記錄要防止的回歸；不因函式存在就寫鏡像測試。結果須附版本、環境、執行範圍及失敗證據。環境不可用與未執行均須明列，不得標成通過。
