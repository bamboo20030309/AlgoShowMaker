# 驗證集使用手冊

更新：2026-10-06。以下指令從 `algo-vis-backend` 執行；使用自己的 worktree，不使用使用者分頁、草稿或開發服務作測試。

## 先決定要跑哪些

| 改動 | 層級與做法 | 執行者 |
|---|---|---|
| 文件、文字、純 CSS／版面 | V0：差異檢查，有畫面變動才核對畫面 | 開發代理 |
| 編輯、選取、剪貼簿、投影片儲存 | V1：直接相關的小測試；不跑演算法動畫 | 開發代理 |
| 指令、Trace、事件、renderer、camera、keep | V2：相關解析／整合／瀏覽器小測試 | 開發代理 |
| 全部測試、跨模組及大型動畫矩陣 | V3：主代理依實際風險選範圍 | 僅主代理 |

新功能作用於已儲存資料時，必須核對新物件、缺少新欄位的舊物件、自訂值／明確關閉，以及實際載入、使用、儲存與重開。不能只驗證新建物件。

先列出測試索引，這個指令**不執行測試**：

```sh
npm run test:inventory
```

索引提供領域、V 級、服務／編譯器／瀏覽器需求、依賴與成本。分類是自動推估，仍須依修改的資料流選擇。完整權限與 A～M 分類見 [子代理驗證分級通知](../子代理驗證分級通知.md)。

## 小測試怎麼跑

只指定直接相關檔案。例如下列指令驗證續跑與依賴指紋，不啟動演算法動畫：

```sh
node --test tests/validation-evidence.test.js tests/regression-resume.test.js
```

常用選擇：

| 問題 | 測試檔 | 環境 |
|---|---|---|
| 正式範例封裝、Trace ID、來源指紋 | `guest-gallery-assets.test.js` | Node |
| 範例卡片、縮圖、新教材開啟免編譯 | `guest-gallery-contract.browser.test.js` | 瀏覽器；自行建立隔離服務 |
| 舊 Trace 格式／來源相容性 | `trace-bundle-compatibility.test.js` | Node |
| 預設線篩載入、取消、舊設定與快取重開 | `algorithm-default-sieve.browser.test.js` | 瀏覽器；自行建立隔離服務 |
| text＋structure＋code 複製、縮放、儲存重開 | `mixed-object-paste.browser.test.js` | 瀏覽器；自行建立隔離服務 |
| 切換程式後 DOM／記憶體趨勢 | `scene-resource-lifecycle.browser.test.js` | 瀏覽器；自行建立隔離服務 |
| keep、提交時機、錄製器判斷 | `animation-assertions.test.js`、`trace-debug-recorder.test.js` | Node |
| 後端故障恢復、取消、滿佇列與使用者隔離 | `compile-recovery.integration.test.js` | 隔離服務與 C++ 編譯器；MLE 需 Linux |

以正式範例為例，以下指令只核對指定的兩個測試檔：

```sh
node --test tests/guest-gallery-assets.test.js tests/guest-gallery-contract.browser.test.js
```

瀏覽器需要 npm dependencies 與可用瀏覽器。Windows 預設 Edge；其他環境缺少 Chromium 時，`npx playwright install chromium` 用來安裝測試瀏覽器。服務／編譯器需求以測試原始碼及索引為準。

### 需要外部測試服務的檔案

部分測試讀取 `ASM_TEST_BASE_URL`，不自行啟動服務。**不要指向 3000、3100 或其他代理的預覽服務。** 可將以下程式存成被 Git 忽略的 `algo-vis-backend/test-results/run-selected.cjs`，資料夾不存在時先建立：

```js
const { spawn } = require('node:child_process');
const { startIsolatedServer } = require('../tests/helpers/isolated-server');
(async () => {
  const cleanups = [];
  try {
    const { base } = await startIsolatedServer({ after: fn => cleanups.push(fn) });
    const args = process.argv.slice(2);
    if (args[0] === 'scripts/compile-load-test.js') args.push(`--base=${base}`);
    const child = spawn(process.execPath, args, {
      stdio: 'inherit', env: { ...process.env, ASM_TEST_BASE_URL: base }
    });
    process.exitCode = await new Promise((resolve, reject) => {
      child.once('error', reject);
      child.once('exit', code => resolve(code ?? 1));
    });
  } finally {
    for (const cleanup of cleanups.reverse()) await cleanup();
  }
})().catch(error => { console.error(error); process.exitCode = 1; });
```

例如此指令啟動隨機埠、獨立暫存／快取的服務，執行 defaults 指令專項，結束後清理自己的服務：

```sh
node test-results/run-selected.cjs --test tests/defaults-directives.test.js
```

## 主代理動畫與續跑

以下入口全部屬於 V3，子代理不得執行。**PR 目前不會自動觸發大型驗證。**

| 指令 | 用途 |
|---|---|
| `npm run regression` | 靜態檢查、小測試與動畫；續用有效通過紀錄 |
| `npm run regression:tests` | 只執行本輪需要重跑的小測試 |
| `npm run regression:animation` | 只執行本輪需要重跑的動畫／前置契約 |
| 上述名稱加 `:fresh` | 重設共用輪次；只執行該入口的階段，不保留舊輪次的通過證據 |
| `npm run validate:release-v4.11` | v4.11 特定效能增量集合；不能代替通用完整回歸 |

一般修正後使用續跑入口即可。程式、測試、fixture、共用依賴或環境改變時，相關通過證據自動失效；未變更的有效項目不重跑。瀏覽器／服務的動態依賴採保守範圍，可能使多項失效。缺少指紋的舊紀錄不能盲目沿用。

大型矩陣目前有 20 個案例與 3 個前置契約。動畫只在 runtime iframe 錄製；Trace 先建立，再預設使用 3 個 worker 播放。八皇后使用 N=4 核對完整執行結果，陣列／位元版分別錄製前 12／16 幀，並不代表全部幀皆已驗證。

主代理只驗證某些動畫時，可用以下 PowerShell 指令。它選擇兩種 Merge Sort、略過三個前置契約，完成後清除篩選設定：

```powershell
$env:ASM_ANIMATION_CASES = 'merge-recursive,merge-bottom-up'
$env:ASM_ANIMATION_PREREQUISITES = 'none'
try { npm run regression:animation }
finally {
  Remove-Item Env:ASM_ANIMATION_CASES -ErrorAction SilentlyContinue
  Remove-Item Env:ASM_ANIMATION_PREREQUISITES -ErrorAction SilentlyContinue
}
```

Linux 同等指令如下；環境變數只影響這次命令：

```sh
ASM_ANIMATION_CASES=merge-recursive,merge-bottom-up ASM_ANIMATION_PREREQUISITES=none npm run regression:animation
```

局部動畫結果不會把完整輪次標成通過。需要儲存／匯入核實時，不應略過相關前置契約。可選案例名稱以 `test:inventory` 的 `animationCases` 為準；追查競態或資源受限時，可將 `ASM_ANIMATION_WORKERS` 設為 `1`。

## 故障恢復與多人壓測

下列指令使用已有的 `algo-vis-backend-backend` Docker image，在自動移除的 Linux 容器跑故障恢復；不公開埠、不掛載使用者資料庫，程式來源唯讀：

```sh
npm run validate:backend-linux
```

需要 Docker 與已建置映像；不同 image 可透過 `ASM_TEST_DOCKER_IMAGE` 指定。Windows 的 MLE 案例會明確略過，不能算作通過；記憶體限制必須在 Linux 核實。

佇列、限制或演示容量有變動時，由主代理選壓測情境。在上述隔離 runner 內，以下指令送出 50 個快取情境請求，並以 5 秒分批抵達：

```sh
node test-results/run-selected.cjs scripts/compile-load-test.js --scenario=cache --clients=50 --ramp-seconds=5
```

runner 自動將隔離服務網址傳給壓測的 `--base` 參數；壓測 CLI 本身不讀取 `ASM_TEST_BASE_URL`。

其他情境：`cold` 為不同程式的冷編譯、`mixed` 混合快取與冷編譯、`isolation` 檢查不同使用者錯誤訊息、`limits` 檢查正常／TLE／OLE／MLE（Linux）。看成功數、延遲、佇列峰值與最後資源是否歸零。50 個快取請求成功，不等於 50 份大型冷編譯或其他硬體也有相同容量。

## 失敗與交付

結果放在 `algo-vis-backend/test-results/`，不提交 Git：

| 檔案 | 用途 |
|---|---|
| `regression-state.json` | 輪次、通過／待跑項目與指紋失效紀錄 |
| `regression.tap` | 小測試執行結果 |
| `animation/<時間>/summary.json` | 動畫結果與第一個違規 |
| 同目錄的案例 JSON、failure-window 與 PNG | 實際取樣、失敗附近狀態與畫面 |
| `release-v4.11-state.json` | 特定發布候選的增量證據 |

失敗先找第一個違規時間點，依解析、runtime、model、排程與 SVG 追查，修正後續跑。不得刪除失敗紀錄、放寬容許值或更換基準來宣稱通過。服務／編譯器／瀏覽器不可用應列為未完成；錄製截斷或無法序列化也不能算通過。

交付至少記錄：基準與提交、修改範圍／V 級、執行指令與環境、通過／失敗／未執行項目、舊資料往返、報告位置。效能時間與 heap 先建立固定環境基準，不憑空設定門檻。

設計與覆蓋範圍見 [驗證集設計](驗證集設計.md)，更細的專項說明見 [tests README](../algo-vis-backend/tests/README.md)。
