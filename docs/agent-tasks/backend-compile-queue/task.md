# 後端編譯佇列與工作隔離

## 目標

- 保留目前 Docker 的 `0.5 CPU / 1 GB / 128 PIDs` 上限。
- 以單一編譯 Worker 保護展示主機，尖峰請求公平排隊。
- 讓登入帳號或匿名瀏覽器各自擁有排程身分，避免校園共用 IP 互相占用額度。
- 將 `debug_log` 改為每個工作獨立保存。
- 限制編譯器執行時間與錯誤輸出，並保留程式執行的 TLE／OLE／MLE／RE 分類。
- 重複的 trace 靜態分析使用小型記憶體快取。

## 本階段界線

- 維持既有同步 `POST /compile` 回應契約，前端不需改用輪詢。
- 工作佇列模組具備同 key 的執行中去重能力；HTTP 編譯結果尚未抽成可共享物件，因此本階段不在不同 HTTP 回應之間啟用編譯結果去重。
- 持久化執行檔／trace 快取、非同步 Job API 與 cgroup v2 精準 MLE 判定留待後續階段。
