# 雲端儲存前補齊動畫引用

## 問題與結果

只上傳 pendingUploads 標記結果會漏掉匯入的既有 Trace ID，導致雲端提交時報「動畫或素材尚未完整上傳」。本次在儲存快照前逐一核實全部動畫引用；伺服器已完整的結果只讀分塊 metadata，不下載 Trace、不重編譯。缺少／部分上傳時先使用本機快取補傳，已有的分塊不重傳；本機與伺服器均缺少結果時才沿用缺失重建流程，逐一分析、编譯與執行。

重建後生成內容雜湊 ID，更新待提交快照與對應的即時投影片資料；即時資料已被較新的 RUN、編輯或不同投影片取代時不覆蓋。更新保存到本機草稿，匯出與後續播放使用同一結果。重建／補傳失敗回報第幾張及 ID 前綴，保留原雲端提交。

資源不完整錯誤新增 RESOURCE_INCOMPLETE 與 resourceKey，Trace 載入可據此重建而不把所有 HTTP 400 當缺失。權限／網路等其他錯誤仍不觸發重編譯。舊版已保存但尚未分塊的結果由資源狀態回報 legacyAvailable，再由既有提交遷移，不先下載到瀏覽器重傳；retainHistory 保留 undo 可引用的舊結果。

手動 RUN 成功並在動畫編輯器按儲存後，既有 detachDeck 流程將完整結果分離、更新該張 ID；新雲端流程會核實／上傳它，匯出則讀同一份資料。ID 依 Trace 內容計算，結果相同可以不變；未儲存的編輯器草稿仍不自動覆蓋投影片。

## 驗證

V2 的結果載入／保存分類，未啟動完整 V3。cloud-content 的局部測試涵蓋未標記的匯入 ID 補傳、部分分塊續傳、全部缺失引用重建、更新 ID 後重存不重跑、關閉設定／自訂字體保留、錯誤頁次與旧提交保留、舊資料遷移、undo、雜湊／容量與資源隔離。相關 slide-trace-store、slide-cloud-storage 與入口測試核實通過；初次發現的兩個產品回歸（undo 歷史與舊結果遷移）修正後續跑通過。

cloud-trace-repair.browser 使用獨立服務與 headless Edge，模擬雲端資源儲存與真正 C++ 編譯。結果：目前頁與未觀看的第二張均修復，實際雲端快照全部資源通過雜湊核實；手動 RUN 後輸出 24，編輯器儲存後雲端與實際下載 .asmdeck 的 Trace ID 一致，第二張 ID 也一致。重新整理取得保存的新程式，不新增編譯。測試的雲端儲存是隔離 fixture，未更動使用者資料；不宣稱此次直接驗收正式 MongoDB。
