# Trace 快取與階段更新

## 什麼時候更新

一般文字、UI、動畫速度或播放器修正，沿用已儲存 Trace，由新版播放器呈現。程式碼、輸入、繪圖指令或 Trace 生成依賴改變時，才需要新的結果。

`/api/trace/version` 回傳目前生成指紋，禁止 HTTP 快取。指紋涵蓋插樁器、runtime 標頭與來源／呈現設定處理；換行正規化後計算，避免 Windows／Linux 換行不同造成誤判，不包含介面與播放動畫檔。原生執行檔另有編譯器、平台及標頭指紋，跨環境不會誤用。

## 載入與儲存

1. 載入要看的動畫，核對來源、輸入及生成指紋；舊資料缺少指紋也列為需要更新。
2. 過期時顯示紅點／更新中，先不播放舊結果。透過全站背景工作取得新 Trace，同內容工作合併執行，各瀏覽器仍有獨立授權的工作 ID。
3. 成功後保存完整新結果到獨立快取，更新投影片的 Trace ID，再讓播放器載入完整結果。後續播放、匯出、本機草稿及雲端儲存使用同一引用。
4. 失敗保留原來源與引用、保持紅點，提供「重試更新動畫」。一般導覽不反覆重送失敗工作。更新途中若使用者已修改程式，舊工作不得覆蓋新內容。

紅點代表動畫需要更新，不等於投影片尚未儲存；動畫更新不會把尚未成功的雲端儲存冒充為已儲存。公開範例仍只在本次開啟的本機副本編輯，不回寫官方教材。

`.asmdeck` 保持精簡，只存程式、輸入、設定及 Trace ID。舊結果不會因為套用呈現設定就被重新蓋上「最新版」標記。

## 階段完成／發布前

從 `algo-vis-backend` 目錄執行，下例網址應換成專屬建置或隔離服務：

```bash
npm run prebuild:guest-decks -- --base-url http://127.0.0.1:3100 --rerun
npm run prebuild:guest-decks -- --base-url http://127.0.0.1:3100 --verify-only
```

第一行逐份重新執行所有公開動畫，忽略完整結果快取，但可沿用相容執行檔；不是略過執行或資源限制。第二行只核對來源、輸入、生成指紋、內容 ID 與檔案完整性，不重新執行演算法。這些完整性檢查不能代替演算法標準答案與動畫行為驗證，仍須按變更範圍跑相關驗證。

`--only merge-sort` 限定重建單份教材；正式階段更新應省略 `--only`。`--force` 會連執行檔快取也略過，通常不需要。`--public-root` 用於測試的獨立教材目錄，不要指向其他專案。

## 切換與保留

先在暫存目錄建立及核對全部選定結果，再把帶完整內容雜湊的 Trace、asmdeck 和預設動畫檔放到位，最後切換索引／清單。中途編譯失敗不更新公開清單。

- `guest-decks.json`：每次開啟重新讀取，指向當前不可變教材檔。
- `deck-traces/index.json`：ID 到檔案的索引，保留舊 ID；新 Trace 使用帶雜湊檔名，避免同 URL 被覆寫而混用快取。
- `guest-decks/<name>.asmdeck`：保留可讀的最新編製來源；`source_archive` 指向此檔，公開 `archive` 指向不可變版本。
- `default-animation/manifest.json`：預設線篩的預覽與完整動畫都使用不可變檔名；版本不符時不先展示舊預覽。

不自動刪除舊結果，因為使用者的既有投影片可能仍引用它們。後續清理需另做引用核對與保留期規劃，不能僅依檔案日期刪除。
