# 執行檔與 Trace 的生命週期

2026-11-16 起不再持久保存 Trace 結果；本規則取代先前的預建 Trace／Trace ID 快取。

## 載入投影片

1. 先讀投影片內容與設定，畫面不必等所有動畫執行完畢。
2. 按水平頁順序、各頁內由上往下，從第一個動畫開始逐份執行；跳頁不改變準備順序。
3. 後端重用相容的原生執行檔；每次都以目前輸入重新執行，產生本次使用的 Trace。
4. 完成的 Trace 只留在目前頁面的記憶體，可供播放與重看。重新整理或關閉後丟棄。
5. 單個動畫失敗會保留來源與錯誤資訊，繼續準備後面的動畫；明確重試才重送失敗項目。

執行仍經過全站佇列、時間／記憶體／輸出限制；使用執行檔快取不會跳過這些限制。相同的進行中工作可合併，已完成結果不作跨次重播快取。

## 保存什麼

| 位置 | 保存內容 |
| --- | --- |
| `.asmdeck`、本機草稿、雲端投影片 | 程式碼、輸入、顯示／事件設定、`executableRef.id`，以及原本的文字、圖片等內容 |
| 伺服器執行檔快取 | 本機平台可用的執行檔與校驗／版本資訊 |
| 目前頁面記憶體 | 本次執行的完整 Trace；內部短期 ID 不會寫入投影片 |
| 非同步工作傳輸區 | 尚在傳送的回應；所有合併工作的觀看者收到後即刪除，未下載的回應預設兩分鐘到期 |

執行檔 ID 是提示，伺服器仍根據來源、插樁、編譯器與編譯旗標核對真正的快取鍵。換機、換平台、快取被淘汰或引擎不相容時會重新編譯，不接受瀏覽器提供的原生二進位直接執行。

儲存與匯出不要求動畫先 RUN 完；它們保存最新程式與設定，下次開啟再執行。手動 RUN 的新設定與執行檔 ID 會在動畫儲存回投影片時一併更新。

## 執行檔保留期限

- **官方公開範例永久保留**：伺服器依目前的公開教材清單及演算法範例原始碼辨識，固定保存相容的執行檔，不因 7 天期限或容量清理而淘汰；重啟服務後仍保留。既有官方執行檔會自動升級保留設定，不必重編譯。
- **使用者程式暫存**：預設自建立起 168 小時（7 天）；容量不足時可提前依最近使用時間淘汰。修改官方範例的程式碼後也按此規則處理，使用者不能自行指定永久保留。
- **換輸入仍重用**：輸入不影響執行檔 ID；同一官方程式換測資只需重新執行。每次執行仍產生新的當次 Trace，不恢復 Trace 持久快取。
- **版本相容性**：來源、編譯器、標頭或引擎改變時建立新執行檔；目前官方版本的新執行檔同樣固定保留。已撤下且不再被官方來源使用，或已不相容的舊執行檔，解除固定保留並重新給予一般暫存期限。
- **儲存位置**：預設位於後端的 `artifact-cache-data/executable/`（可用 `ARTIFACT_CACHE_DIR` 調整），不提交 Git。若部署在容器中，需保留該快取資料卷；刪除資料卷、換機或手動清空後，仍需重新編譯。
- 官方可保留的追蹤設定限預設、全部變數及教材原有的選取組合；任意自訂變數子集仍屬暫存，避免產生無限多份永久變體。

## 舊資料遷移與刪除

- 公開教材與歷史封裝移除內嵌結果及舊 Trace 引用，保留來源、輸入和自訂設定。
- 本機草稿資料庫升級到 schema 2，清空舊 Trace store；原本的草稿內容與明確關閉設定保留。
- 開啟介面時刪除兩個舊 Trace IndexedDB 快取；若舊分頁阻擋資料庫升級，應關閉舊分頁再重新整理。
- 服務啟動時清除舊結果快取，逐份將雲端資料轉為來源配方，再清除舊結果資源；遷移失敗則保留原資料並記錄原因。
- 已停用 `/deck-traces/*` 及舊投影片 `/traces/:id` 結果端點。舊客戶端不得再上傳完整 Trace。
- 無法取得程式碼的舊結果必須明確報錯，不靜默丟棄無法重建的內容。

Git 刪除只移除目前分支的追蹤檔案，不改寫歷史提交；主分支需經使用者另行授權合併。

## 教材發布準備

在 `algo-vis-backend` 目錄執行，網址請指向整合或獨立建置服務：

```bash
npm run prebuild:guest-decks -- --prewarm --base-url http://127.0.0.1:3100
npm run prebuild:guest-decks -- --verify-only
```

第一行依序執行教材並預備執行檔，只把 ID 寫回教材，不輸出 Trace 資產。第二行核對公開封裝雜湊、來源、執行檔 ID 及沒有結果 payload，不執行動畫。執行成功不等同動畫行為正確，行為驗證仍使用獨立標準答案。
